# Scientific issues and open gates

Implemented code is not automatically empirical evidence. The following items
remain open.

| ID | Status | Issue | Required evidence |
|---|---|---|---|
| D0-01 | improved, open | Selective requests preserve more resource dimensions, but final global dimensions are still only 1.737–2.004 rather than the no-entity audit near four. | Repeat v0.38 explicit request analysis; distinguish external-field generation, requested composition and realized extraction. |
| D1-01 | active | Four capacities retain 3.456–3.761 effective dimensions, but cross-sectional variation does not prove adaptive selection. | Same-checkpoint capacity-neutral branches across seeds/phases; report use, energy, survival and knowledge/social outcomes. |
| D1-02 | active | Working memory is almost always saturated, so its upper bound or update semantics may be too tight. | Capacity-bound sensitivity and paired neutralization; do not raise the bound solely to manufacture variation. |
| D1-03 | active | Realized harvest channel volumes co-move with population and action count. | Use explicit requested-channel shares from v0.38; never infer old selective requests from realized output. |
| D1-04 | active | Affinity and capacity may interact, so one-at-a-time ablations can misattribute effects. | Four-branch affinity × capacity factorial contrast from a shared checkpoint. |
| D1-05 | open | High capacity use can reflect binding constraints without fitness benefit. | Measure expression effects over fixed horizons and multiple phases; separate maintenance/development cost from downstream benefit. |
| D2-01 | blocked | Universal functional modules would overlap existing policy, latent routing and knowledge mechanisms. | Enter D2 only after D1 expression effects and niche-dependent trade-offs repeat in at least two seeds. |
| ENV-01 | open | Share vectors are compositional and correlations among shares are descriptive. | Interpret share dimensions jointly with raw volumes, extraction efficiency and paired interventions; avoid causal claims from correlation alone. |
| GPU-01 | open | User runs use GPU strict-reference with acceleration disabled. | Validate hybrid accelerated multi-tick parity separately from scientific conclusions. |
| REL-01 | guarded | Source-tree tests can pass while wheel/sdist is incomplete or an old install is imported. | Run disposable-venv sdist→wheel validation for every release candidate. |
