# v0.4 实现状态

版本：0.4.0

## 实现边界

本版本以 CPU 参考实现作为语义对照，并提供显式 GPU 混合执行路径；它不是完整设备驻留世界循环。GPU 模式下环境/信息场在设备上权威演进和提交，实体、关系、出生死亡和主体图当前由 CPU 提交。权威写入属于通过版本或计划校验的提交器，不永久绑定某种硬件；策略、观察和冲突解析阶段仍不得直接改写世界。

模型启发式、解释风险和暂缓但有科学价值的问题统一登记在 `SCIENTIFIC_ISSUES.md`；“已实现”只表示实验机制可运行，不表示相关科学假设已经成立。

## 当前社会主体的含义

当前群体节点是候选主体而不是本体论结论。群体由高信任关系形成，其成员资源梯度被压缩成群体方向。群体方向进入行动语义，但个体对社会观察和相关行动的权衡全部来自其遗传策略矩阵。

`control.heuristic_social_guidance=true` 会直接修改已采样移动方向，因此必须同时使用 `run.experiment_mode="entertainment"`。它仍记录双控制器贡献，但不能被解释为主体性评分、因果归因或科学基线的一部分。

## 已知简化

- 群体识别采用固定轮数标签传播，是近似连通分量；
- 固定 8 轮传播是原有模型近似而非本阶段新增的性能启发式；阶段 9 只改变规划/提交边界和精确等价的数据组织；
- 社会依赖是能量来源比例代理指标，不是完整主体偏移判定；
- 候选主体图为低频快照，尚不是任意嵌套的图数据库；
- GPU/CPU 仍有显式的动态状态和结果传输；关系、生命周期提交、主体图和 CSV/检查点仍在 CPU，完整设备驻留循环尚未完成；生命周期计划已与 CPU 容器解耦，但设备迁移必须同时设计持久实体 SoA、活动集、槽池和主体图写入，不能只搬运小型规划核；
- 持久实体镜像已经消除 routine tick 的完整 static/social 上传，但 CPU 最终动态值仍通过 `EntityDeviceCommitPlan` 同步；设备观察压缩与更多实体迁移因缺少端到端收益暂缓，不能让策略借迁移之名成为世界写者；
- CPU 默认解析器是严格参考实现；GPU 默认解析器只迁移采集子计划。GPU/分布式解析器必须返回相同的 `ActionResolutionPlan` 合约；解析阶段不写世界，但消费已解析计划的受控提交器可位于 CPU、GPU 或分布式分区；
- 关系事件已有后端无关计划，但固定槽关系表仍由 CPU 持有；只把事件排序放到 GPU 会增加传输，后续设备迁移必须同时设计持久槽镜像和群体读取边界；
- 默认仲裁器只接受每个承载体一个身体提案；社会方向引导仲裁器是目前随配置提供的双提案实现，并只做方向混合。加权动作重采样、优先级、否决或竞价仍须另行验证后接入；
- `AutonomyRecoveryArbiter` 和社会方向混合均隔离在娱乐协议；前者直接替换行动类别，后者覆盖移动方向，二者结果不得并入基础演化或主体偏移证据；
- 线性策略架构、特征词汇和记忆动力学仍是约束策略空间的模型选择；虽不再指定行动偏好，正式结论仍需架构与初代分布敏感性分析；
- 利益边界目前只测实际分享能量；群体又由分享累积出的信任关系识别，因此当前内聚指标有循环相关，不能单独证明主体边界；
- 滞后利益边界已按稳定实体 ID 冻结一个评估窗口，并与即时五类无损流并列输出；它降低同窗循环定义，却不能消除群体形成的历史选择偏差。局部伙伴机会率零模型及物质/风险/信息收益流尚未实现；即时、滞后、累计和活跃主体指标仍必须按各自分母解释；
- 当前配置的繁殖容量冲突使用 `stateless-random-v1`；缺少新字段的归档配置保持 `stable-id-v1`。这只消除了仲裁排序的低 ID 优势：同 tick 死亡仍不释放本 tick 出生槽位，容量失败仍不支付繁殖成本，真实繁殖机会还受年龄、位置、能量和策略选择影响；
- 每 500 tick 的演化评估对最多 4096 个稳定哈希抽样承载体计算策略 SVD、固定探针概率和真实上下文响应，并以最多 1024 个策略 × 32 个真实上下文构造共同面板；这是明确的只读诊断抽样，不反馈模型，100k 全体谱系集中度仍精确计算；单 tick 响应不是策略—长期后果的因果估计；
- 延迟直接消息仍由 CPU 队列保存，接收、噪声和容量裁决均批量向量化；当前设备策略只消费消息语义均值，槽级元数据保留在稀疏计划中供未来注意力策略按需物化；
- 当前字段、观察和策略输入仍固定为资源/危险/社会三个通道；`SignalEmissionPlan` 已支持异频稀疏发射，但可配置通道 schema、每通道传播参数和异步传播仍需作为模型语义阶段单独实现；
- 普通主体网络没有在线反向传播；
- 资源模型仍是第一版抽象，并非完整化学或生态系统。

## 已验证基准

本工作区的 v0.4 冒烟和 GPU 对照结果，仅用于正确性与规模参考：

下列既有 100k/300 tick 墙钟来自固定行为公式被移除之前，只用于记录历史性能工作，不能代表当前 136 列演化基因组的吞吐。新策略阶段暂不恢复性能优化；已完成的当前规模检查是 100k/5 tick CUDA 显存与执行冒烟，预热后窗口约 `0.081秒/tick`，该短窗口不作为性能承诺。

- 5,000初始实体、500步：约0.03秒/步；
- 稀疏突变后的单种子 2,000 tick GPU 诊断：平均/最高世代 `3.57/10`，有效谱系从 tick 500 的约 `731` 降到 `45`，最大谱系占比升至 `9.46%`；规范策略多样性仍为初始的 `97.75%`，固定探针行为概率多样性为 `99.29%`。谱系已结构性集中而策略函数未同步集中，说明当前环境/行动收益的策略选择梯度仍不足，不能把两类坍缩等同；
- 同次运行的累计利益边界内聚为 `0.324`，各 500 tick 窗口从 `0.296` 上升到约 `0.345`：已有弱内聚趋势，但当前已形成边界相关的分享仍多数跨越边界。该数值受群体检测定义影响，只用于暴露问题，不是主体否定结论；
- 直接消息、意图结算和主体图均启用；
- WSL2、NVIDIA GeForce RTX 4070、CUDA Toolkit 13.3 与 `cupy-cuda13x==14.1.1`：完整测试套件通过，含稀疏遗传、周期演化评估、繁殖闭环、即时/滞后利益流守恒、真实策略上下文下载、环境反转、娱乐行动覆盖和共享设备前史分叉的 CPU/GPU 对照；
- 5,000 初始实体、1,000 tick GPU 两窗口冒烟中，记录的滞后边界 snapshot 依次为 tick `0/500`，两窗即时与滞后分类残差均为 `0`；第二窗即时/滞后边界覆盖率分别为 `0.843/0.526`、内聚分别为 `0.318/0.142`。差异说明即时边界确会高估同窗形成边界下的内聚，不作为跨种子科学结论；
- `stateless-random-v1` 的 128 种子隔离容量压力对照将稳定 ID 四分位接受率从旧规则的 `1/0/0/0` 改为 `0.2474/0.2528/0.2509/0.2489`；100k/300 tick GPU 冒烟记录 525,969 个繁殖提案、78,278 个接受和 447,691 个容量拒绝，闭环残差为 0，墙钟约 32.8 秒但不作为性能比较；
- 同一环境下，`verify_gpu_foundation.py --ticks 16` 通过，字段最大绝对误差为 `2.12e-6`（容差 `5e-6`）。
- 关系维护优化前后，同一台机器的已预热 `cProfile` 单 step 分别为约 `0.112/0.077秒`；前者中的整表关系衰减和死链接扫描热点已消失。该剖析结果不等于完整吞吐承诺。
- GPU 融合随机键将同一已预热剖析中随机键/Uniform 相关累计时间由约 `18ms` 降至约 `6ms`；逐位随机键和 CPU/GPU 端到端对照均通过。
- 三通道稠密共享排序在 131,072 事件微基准中虽可从 `3.772ms` 降至 `1.182ms`，但 300 tick 端到端运行没有可测提升，且会把异频通道强制为零填充矩阵；因此未作为默认路径保留。
- 默认 `[1,1,1]` 稀疏直通计划的另一轮 100,000 初始实体、300 tick GPU 实跑为 `31.53秒`（最后 20 tick 窗口 `0.100秒/步`）。该数据确认没有可宣称的稠密批量吞吐收益；不同单次墙钟仅作为机器状态参考。
- 同一机器、100,000 初始实体、300 tick、禁用 checkpoint 的本次成对测量中，GPU 采集计划为 `31.12秒`，CPU 键构建为 `31.77秒`（约 `2%`）。该小幅收益已通过逐项计划一致性和“计划阶段不改资源”测试；它不是完整设备驻留循环的吞吐承诺。
- 显式关系计划初版的 100,000 实体、300 tick 实跑为 `32.39秒`；消除提交端重复排序/分段并仅在槽满时计算最弱槽后为 `31.34秒`。43,750 事件微基准的固定槽应用由约 `10.95ms` 降至 `5.94ms`；单次端到端差异仍只作为机器状态参考。
- 显式生命周期计划的同状态 100,000 实体、300 tick GPU 运行得到 `30.95/32.60/33.94秒`，tick 300 均为 `alive=130860`；墙钟波动大且没有可宣称的端到端提速。空闲槽池改为只复制本次分配尾段后，20,000 个请求在 100k/1M 槽池上约 `1.62/1.72ms`，相较先复制全池的 `2.58/14.03ms` 不再随池容量线性增长；131,072 活跃实体、1,352 个死亡的事件扫描约 `0.75ms`。
- 稀疏直接消息观察阶段的 100,000 实体、300 tick 严格 GPU 两次为 `25.55/27.14秒`，相对阶段 8 最快的 `30.95秒` 改善约 `12.3%–17.4%`。两次 action counts、出生死亡、群体数、主体边和图版本均与基线一致。tick 300 接受 4,145 条直接消息时，整步显式 H2D/D2H 为 `16,788,152/10,436,876 bytes`，并规避 `62,726,060 bytes` 的稠密消息主机上传；设备仍按原容量宽度对实际接收者归约，以保持长期离散轨迹。
- 群体计划阶段在 100k active、45,016 成员、2,648 群体的隔离基准中，将候选主体图提交由约 `0.335–0.353秒` 降至约 `0.0244秒`（预热中位数约 `14.1×`）；21 万历史节点的 summary 由约 `14.1ms` 降至约 `0.36µs`。同配置 100k/300 tick 严格 GPU 两次为 `27.72/29.14秒`，最终动作与离散状态逐项一致，但相对阶段 8.5 没有可宣称的端到端提升；低频图提交收益被每 tick GPU 阶段和机器波动淹没。
- 持久实体镜像阶段的最终 100k/300 tick 严格 GPU 为 `27.62秒`；tick 300 H2D 从 `16,788,152` 降至 `9,345,128 bytes`（44.3%），D2H 保持 `10,436,876 bytes`，版本化实体提交为 `5,270,960 bytes`、约 `2.49ms`。动作计数和最终离散状态与阶段 8.5 完全一致；墙钟仍处于既有波动区间，不宣称端到端提速。被淘汰的全稀疏散射初版为 `34.84秒`，说明传输字节和执行成本必须同时测量。

实际速度依赖CPU、Python和NumPy版本。
