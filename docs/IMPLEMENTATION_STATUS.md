# v0.4 实现状态

版本：0.4.0

## 实现边界

本版本以 CPU 参考实现为世界语义权威，并提供显式 GPU 混合执行路径；它不是完整设备驻留世界循环。字段、空间、观察、策略和采集冲突子计划在 GPU 上运行，CPU 仍负责统一世界提交、关系、出生死亡和主体图，使每个主机/设备边界可审计。

## 当前社会主体的含义

当前群体节点是候选主体而不是本体论结论。群体由高信任关系形成，其成员资源梯度被压缩成群体方向。群体方向通过独立控制通道影响成员，但影响强度仍取决于成员遗传社会倾向和动作采样。

`control.heuristic_social_guidance=true` 启用当前已实现的社会方向控制规则：稳定社会主体对已由身体策略选中的 `MOVE_RESOURCE` 方向按 0–1 权重做归一化混合，并记录双控制器贡献；它不改变行动类别、mask 或随机流。方向混合是明确的建模启发式，不能被解释为主体性评分、因果归因或已校准的社会决策模型。

## 已知简化

- 群体识别采用固定轮数标签传播，是近似连通分量；
- 固定 8 轮传播是原有模型近似而非本阶段新增的性能启发式；阶段 9 只改变规划/提交边界和精确等价的数据组织；
- 社会依赖是能量来源比例代理指标，不是完整主体偏移判定；
- 候选主体图为低频快照，尚不是任意嵌套的图数据库；
- GPU/CPU 仍有显式的动态状态和结果传输；关系、生命周期提交、主体图和 CSV/检查点仍在 CPU，完整设备驻留循环尚未完成；生命周期计划已与 CPU 容器解耦，但设备迁移必须同时设计持久实体 SoA、活动集、槽池和主体图写入，不能只搬运小型规划核；
- CPU 默认解析器是严格参考实现；GPU 默认解析器只迁移采集子计划。GPU/分布式解析器必须返回相同的 `ActionResolutionPlan` 合约，不得直接写世界；
- 关系事件已有后端无关计划，但固定槽关系表仍由 CPU 持有；只把事件排序放到 GPU 会增加传输，后续设备迁移必须同时设计持久槽镜像和群体读取边界；
- 默认仲裁器只接受每个承载体一个身体提案；社会方向引导仲裁器是目前随配置提供的双提案实现，并只做方向混合。加权动作重采样、优先级、否决或竞价仍须另行验证后接入；
- 社会方向混合是当前模型的启发式规则。它默认关闭以维持基线可比性，实验结果必须按 `run_metadata.json` 的控制配置与受引导行动数分层报告；
- 延迟直接消息仍由 CPU 队列保存，接收、噪声和容量裁决均批量向量化；当前设备策略只消费消息语义均值，槽级元数据保留在稀疏计划中供未来注意力策略按需物化；
- 当前字段、观察和策略输入仍固定为资源/危险/社会三个通道；`SignalEmissionPlan` 已支持异频稀疏发射，但可配置通道 schema、每通道传播参数和异步传播仍需作为模型语义阶段单独实现；
- 普通主体网络没有在线反向传播；
- 资源模型仍是第一版抽象，并非完整化学或生态系统。

## 已验证基准

本工作区的 v0.4 冒烟和 GPU 对照结果，仅用于正确性与规模参考：

- 5,000初始实体、500步：约0.03秒/步；
- 直接消息、意图结算和主体图均启用；
- WSL2、NVIDIA GeForce RTX 4070、CUDA Toolkit 13.3 与 `cupy-cuda13x==14.1.1`：完整测试套件 `66 passed`；
- 同一环境下，`verify_gpu_foundation.py --ticks 16` 通过，字段最大绝对误差为 `2.12e-6`（容差 `5e-6`）。
- 关系维护优化前后，同一台机器的已预热 `cProfile` 单 step 分别为约 `0.112/0.077秒`；前者中的整表关系衰减和死链接扫描热点已消失。该剖析结果不等于完整吞吐承诺。
- GPU 融合随机键将同一已预热剖析中随机键/Uniform 相关累计时间由约 `18ms` 降至约 `6ms`；逐位随机键和 CPU/GPU 端到端对照均通过。
- 三通道稠密共享排序在 131,072 事件微基准中虽可从 `3.772ms` 降至 `1.182ms`，但 300 tick 端到端运行没有可测提升，且会把异频通道强制为零填充矩阵；因此未作为默认路径保留。
- 默认 `[1,1,1]` 稀疏直通计划的另一轮 100,000 初始实体、300 tick GPU 实跑为 `31.53秒`（最后 20 tick 窗口 `0.100秒/步`）。该数据确认没有可宣称的稠密批量吞吐收益；不同单次墙钟仅作为机器状态参考。
- 同一机器、100,000 初始实体、300 tick、禁用 checkpoint 的本次成对测量中，GPU 采集计划为 `31.12秒`，CPU 键构建为 `31.77秒`（约 `2%`）。该小幅收益已通过逐项计划一致性和“计划阶段不改资源”测试；它不是完整设备驻留循环的吞吐承诺。
- 显式关系计划初版的 100,000 实体、300 tick 实跑为 `32.39秒`；消除提交端重复排序/分段并仅在槽满时计算最弱槽后为 `31.34秒`。43,750 事件微基准的固定槽应用由约 `10.95ms` 降至 `5.94ms`；单次端到端差异仍只作为机器状态参考。
- 显式生命周期计划的同状态 100,000 实体、300 tick GPU 运行得到 `30.95/32.60/33.94秒`，tick 300 均为 `alive=130860`；墙钟波动大且没有可宣称的端到端提速。空闲槽池改为只复制本次分配尾段后，20,000 个请求在 100k/1M 槽池上约 `1.62/1.72ms`，相较先复制全池的 `2.58/14.03ms` 不再随池容量线性增长；131,072 活跃实体、1,352 个死亡的事件扫描约 `0.75ms`。
- 稀疏直接消息观察阶段的 100,000 实体、300 tick 严格 GPU 两次为 `25.55/27.14秒`，相对阶段 8 最快的 `30.95秒` 改善约 `12.3%–17.4%`。两次 action counts、出生死亡、群体数、主体边和图版本均与基线一致。tick 300 接受 4,145 条直接消息时，整步显式 H2D/D2H 为 `16,788,152/10,436,876 bytes`，并规避 `62,726,060 bytes` 的稠密消息主机上传；设备仍按原容量宽度对实际接收者归约，以保持长期离散轨迹。
- 群体计划阶段在 100k active、45,016 成员、2,648 群体的隔离基准中，将候选主体图提交由约 `0.335–0.353秒` 降至约 `0.0244秒`（预热中位数约 `14.1×`）；21 万历史节点的 summary 由约 `14.1ms` 降至约 `0.36µs`。同配置 100k/300 tick 严格 GPU 两次为 `27.72/29.14秒`，最终动作与离散状态逐项一致，但相对阶段 8.5 没有可宣称的端到端提升；低频图提交收益被每 tick GPU 阶段和机器波动淹没。

实际速度依赖CPU、Python和NumPy版本。
