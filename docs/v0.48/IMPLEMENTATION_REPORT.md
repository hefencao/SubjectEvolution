# v0.48 implementation report

## Trigger

The supplied D4-A result showed repeated generic endpoint interaction but no exposure-aligned differentiation. Structural review then found that v1 modules were independent additive copies of one harvest-routing function, so previous ablations could not test inherited module dependency or hierarchy.

## Implemented

- opt-in compositional module schema v2;
- six active inherited lower-to-higher coupling genes;
- bounded multiplicative downstream modulation;
- explicit coupling maintenance/development costs;
- coupling-output-only intervention with genes and costs retained;
- checkpoint and branch persistence;
- v2 contribution and hierarchy diagnostics;
- paired fresh-population D2-I runner and CLI;
- descriptive multi-seed capability summary rather than a continuation gate;
- D4-A assessment v2 requiring exposure alignment before confirmation;
- v1 authoritative compatibility preserved.

## Not implemented

- module duplication or deletion;
- arbitrary dynamic routing;
- feedback/recurrent coupling;
- new resource, sensor, movement, conversion, storage, signal or social ports;
- a stable niche or subjecthood claim.

The remaining harvest-only output limitation is explicit. If v2 coupling is used without increasing persistent functional dimensionality, the next redesign target is the versioned primitive/output vocabulary.
