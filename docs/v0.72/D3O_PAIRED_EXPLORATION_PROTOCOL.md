# D3-O fixed-checkpoint paired exploration protocol

## Objective

Measure candidate mechanisms cheaply without confusing the common initialization transient with a treatment effect.

## Source boundary

A source checkpoint can support an acute paired panel when it meets scale-normalized minimums:

- living entities: `max(64, 8% of initial population)`;
- effective founder lineages: `max(32, 4% of initial population)`;
- largest founder-lineage fraction: at most 25%;
- current strategy effective dimensions: at least 4 in the readiness audit.

These checks do not claim demographic turnover, a stable source population, or valid long-horizon selection. They only establish enough state for a short matched mechanism response.

## Pairing

For each independent seed:

1. load the exact predeclared full checkpoint;
2. verify its file hash, tick, seed, and shared configuration semantics;
3. continue a baseline branch;
4. clone the same checkpoint state and apply one scientific intervention;
5. run both branches for the same fixed response horizon;
6. calculate intervention response minus baseline response.

Cumulative metrics subtract their shared pre-intervention value before the branch contrast. Endpoint metrics compare branch endpoints directly.

## Promotion

A screen requires at least eight eligible seed panels. By default:

- at least 75% of planned seeds must remain eligible;
- at least 75% of eligible seed effects must share the predeclared direction, or one common direction for a two-sided screen;
- the equal-seed median relative effect must reach the predeclared practical threshold.

The exact two-sided sign-flip statistic is reported descriptively. It does not replace the practical-effect and direction-replication gates.

## Scope

A passing paired screen supports only a short checkpoint-phase mechanism effect. It does not establish stable evolution, coexistence, migration, specialization, ecotypes, or a population source rule.
