# v0.104 D1-W：纪元基线与区域分支基础

## 科学判断

当前 SHARE 成功/失败仍通过固定常数更新 trust，group 仍是 trust 超阈值后的连通分量。因此现有 group 只能作为观测结构，不能被称为利益反馈网络、实体主体或 group 主体。

项目改用分纪元治理：长期大规模演化负责跨越涌现门；一旦预注册门通过，就把完整 checkpoint 冻结为下一纪元 base。后续机制开发可以从该基线分支，不必重复运行整个前史。

## 纪元门

- Epoch 0：生态承载体与结构化环境。
- Epoch 1：利益反馈关系网络有效，形成实体主体雏形。
- Epoch 2：group 自有规章可持续约束成员并影响 group 延续，形成 group 主体雏形。

名称不是奖励或控制器。进入门必须由独立 seeds、长期持续、共享 checkpoint 中和及明确证据合同支持。

## 区域分支 v1

实现 `regional-active-set-branch-v1`：

- 保留完整环境坐标系、网格、资源、地形、信号介质和时间相位；
- 保留区域内实体全部状态、谱系、基因、知识及内部关系；
- 移除区域外实体、跨边界关系和跨边界延迟消息；
- 清空尚未提交的场信号队列；
- 将裁剪操作写入 checkpoint lineage 和 intervention history。

它能降低活跃实体规模，但不是物理网格裁剪。真正缩小网格前必须实现源坐标偏移、halo 或开放边界通量，以及裁剪后的松弛期合同。

## 工程变化

- 新增 `se-epoch`：`show`、`freeze-base`、`region-plan`、`region-branch`。
- 新增版本化 epoch registry。
- epoch base 同时冻结 checkpoint、qualification、registry 和 SHA-256 lock。
- 未通过或 checkpoint 哈希不匹配的 qualification 不能生成 base。
- 区域分支可恢复并继续执行，且不把裁剪实体记为生物死亡。

## 证据边界

本版本完成基础设施和可恢复性验证，没有任何 checkpoint 被宣称为 Epoch 1 或 Epoch 2 正式起点，也没有实现 group 规章或利益反馈关系更新。
