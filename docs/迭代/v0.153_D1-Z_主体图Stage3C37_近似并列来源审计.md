## 问题

Stage 3C-35 在独立面板停止，是因为 Stage 3C-27 使用 `1e-8` 将 6 个
age-one/older score gap 归入“exact tie”，使 strict fraction 低于 0.99。Stage
3C-36 无法从聚合结果判断这些事件是真实 runtime tie、归一化方向重复、
float32 坐标压缩，还是只落入较宽的诊断容差。

## 方法

对原面板与独立面板的 rank-two source checkpoint 进行确定性重放，并要求：

1. source/pre-bootstrap state hash 与冻结报告逐 seed 一致；
2. Stage 3C-27 的 multi-candidate、strict、near-tie、older 计数逐 seed精确重现；
3. stored winner identity 与 runtime comparator 精确重建；
4. 对全部 near-tie query 导出原始 float32 三坐标、float64 runtime score、
   direct-float32 反事实 score、归一化方向、共线残差和 ULP 距离。

runtime 实际先把 float32 token 转为 float64，再计算 cosine score；只有 score 在
`1e-12` 内相等时才使用 latest tie-break。Stage 3C-27 的 `1e-8` 仅是分析分箱。

## 冻结结果

- 两面板共 1,728 个 multi-candidate query；
- Stage 3C-27 诊断 near-tie：7；
- runtime comparator tie：0；
- latest tie-break 改变 winner：0；
- 归一化方向完全重复：0；
- 7 个 score gap 全为正，范围 `4.42e-9–7.37e-9`；
- 第二坐标差异为 1,715–2,140 个 float32 ULP；
- selector-consistent strict fraction：原面板 1.0，独立面板 1.0。

直接使用 float32 做 cosine 的反事实结果在 7 个事件中出现 4 个相等、1 个保持
顺序、2 个反转，但 runtime 不使用这一算术路径，因此不能据此解释实际 winner。

## 结论

Stage 3C-35 的停止不是 runtime latest-on-tie 机制导致，也不是候选方向重复。
它来自 Stage 3C-27 将 `1e-8` 诊断分箱命名并解释为 runtime tie。历史 artifact
保持 checksum 不变，不做追溯重写；Stage 3C-37 提供显式的 selector-consistent
qualification overlay。

Stage 3C-35 的 crossing 预测仍然**未测试**，不是已支持或已反驳。下一步 Stage
3C-38 可以在相同独立面板上恢复冻结的 Stage 3C-28→crossing replication 链，
但不得修改 source、addressing、exposure、horizon、runtime comparator 或 crossing
定义。
