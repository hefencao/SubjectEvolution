# v0.91 D1-L：健康代际周转基底与源运行硬门

## 纠正的问题

D1-K 在 tick 720 时仅存活 12、15、19 个实体，平均世代为 0.42、0.27、0.58，
存活者仍以 founder 为主。其后 240 tick 配对虽然可验证 checkpoint 与成本保持，
但不具备基因效应、生态效应或演化解释价值。

此前开发顺序错误地把“新能力是否进入世界”放在“承载该能力的生态是否能健康周转”
之前，并在崩塌后继续生成分析。这会把组合成熟期、能力成本与生态基底失败混为一体。

## 新执行原则

1. 不新增 D1-L 基因；先校准无新能力的代际周转底座。
2. source run 在预注册 tick 进行人口、出生、存活后代、世代深度、founder 比例和阶段跌幅检查。
3. 任一检查失败时，运行干净终止；多个 seed 连续失败时，不再启动剩余 panel。
4. 健康门未通过时，`se-study` 不允许进入 paired-plan 或更长演化阶段。
5. alive 快速下降只有在 study 明确声明为 fast screen 时才允许；该模式不得生成演化解释。
6. 组合能力必须声明成熟窗口，效应测量不能从基因初始化后立即开始。

## D1-K 处置

D1-K 冻结为 `terminate-source-collapse`：保留运行与守恒合同证据，禁止解释配对差异。
后续不再增加 seed、延长该轨迹或从幸存者中筛选“有利”基因。

## D1-L

D1-L 提供参数化 substrate config 生成器和 120/240 tick 分阶段健康门。它只调整明确的
生态通量与固定繁殖预算，不增加基因、不设置能力奖励，也不自动选择参数。
只有三个独立 seed 全部通过后，才允许设计下一项 inherited capability。


## 交付修正

生成配置的规范 sidecar 为 `source_config.json.manifest.json`。生成器、
workflow 前置条件和结果打包器使用同一路径；重新生成时清理旧的
`source_config.manifest.json`。失败健康门结果包同时包含执行配置、sidecar、
panel index、总健康报告和逐阶段事件。
