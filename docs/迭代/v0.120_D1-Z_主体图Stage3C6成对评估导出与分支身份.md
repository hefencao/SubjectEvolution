# v0.120 D1-Z：主体图 Stage 3C-6 成对评估导出与分支身份

## 本轮目标

在 v0.119 的 score-free objective evaluation window 之外建立显式共享 checkpoint 分支与导出合同。该合同解决“单臂窗口不是反事实”的工程缺口，但不在 runtime 内生成 scalar objective、自动 keep/revert 或永久参数授权。

## 已实现

- 新增 `src/se/subject_vm/evaluation_export.py`：
  - 从 Subject VM checkpoint snapshot 提取完成窗口；
  - guarded-live 只接受 verified rollback 完成状态；
  - read-only control 只接受 control 完成状态；
  - 生成不包含 branch mode 的稳定 pair key；
  - 输出逐坐标事实差和显式未配对窗口；
- 新增 `src/se/analysis/subject_vm_paired_evaluation.py`：
  - 创建 Stage 3C-6 计划；
  - 验证可信源 checkpoint 的 file/state/config identity；
  - 拒绝 active window、pending write、locked row 和任何旧 ledger 条目；
  - 从同一 checkpoint 派生 guarded-live 与 read-only-control；
  - 只允许 `subject_vm.live_write.enabled` 不同；
  - branch ID 绑定 source state、role、branch config 和 final tick；
  - 将 branch identity 写入 final checkpoint lineage；
  - 验证两个最终 checkpoint 后导出配对证据；
- 新增命令：

```bash
se-subject-vm-paired-evaluation plan ...
se-subject-vm-paired-evaluation run ...
se-subject-vm-paired-evaluation export ...
```

- checkpoint 配置哈希增加公共只读函数，保持原有 checkpoint identity 算法不变；
- Stage 3C-6 不增加 Subject VM runtime/checkpoint schema，也不改变行动或随机数消费。

## 配对合同

```text
trusted quiescent checkpoint
→ guarded-live branch identity
+ read-only-control branch identity
→ same source state / same final tick
→ completed score-free windows
→ mode-neutral exact window keys
→ component-wise paired export + explicit unpaired records
```

pair key 包含：

- stable subject identity；
- source event identity；
- window start/end tick；
- observed parameter families；
- target kind 和 stable target ID；
- pre/projected value 与 bounded delta。

这避免把仅仅发生在相近时间、但不是同一候选更新合同的窗口错误配对。

## 明确未实现

- scalar score 或固定坐标权重；
- runtime 内部自动 causal attribution；
- 自动 keep/revert；
- 参数永久保留；
- 从未配对窗口中筛掉“不方便”的样本；
- 配对覆盖率或分支分化的科学充分性判定；
- physical cost debit；
- GPU Stage-3 分支执行；
- Epoch 1、学习、适应或主体性结论。

## 科学证据边界

v0.120 只能证明共享 checkpoint、显式 branch identity、完成窗口验证和 component-wise paired export 的工程链路成立。即使某一坐标存在差异，也不能自动说明更新有益、具有主观价值或应永久保留。

下一步应优先建立 Stage 3C-7 paired-evidence adequacy/integrity assessment，检查配对覆盖、未配对原因、rollback failure、fact clipping、branch divergence 和成本匹配，而不是直接建立 scalar objective。
