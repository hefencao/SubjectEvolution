# v0.148：文档治理与类型化任务树

## 进度类型

`[DOC-GOV]`

Git 标题：

```text
[DOC-GOV] reorganize active docs and add typed progress governance
```

## 根因

活动文档逐轮追加后失去职责边界：

- `ARCHITECTURE.md` 混入逐版本实验结果、下一步判断和工程发布边界；
- `SCIENTIFIC_ISSUES.md` 变成按版本累积的结果注释，而不是活跃问题注册表；
- `PROJECT_STATUS.md` 从 Stage 3C-17 起持续堆叠历史结果，并把测试、发布和科学主线混在同一层级；
- 项目缺少仓库级 `AGENTS.md`，无法强制后续代理先分类任务、再选择文档落点。

## 本轮变更

1. 重写 `ARCHITECTURE.md`，仅保留当前结构、所有权、依赖和证据边界。
2. 重写 `SCIENTIFIC_ISSUES.md`，仅保留带 ID、状态和下一证据边界的活跃问题。
3. 重写 `PROJECT_STATUS.md`，建立类型化任务进度树。
4. 新增 `docs/results/SUBJECT_VM_STAGE3C_RESULTS.md`，集中保存冻结的 Stage 3C 结果链。
5. 新增根目录 `AGENTS.md`，强制 Git 标题、分支策略、文档落点、实验治理和交付规则。
6. 保存 v0.147 三份活动文档为明确标记的非规范历史快照。
7. 新增文档治理回归测试，禁止再次把逐版本结果塞回活动文档。

## 科学状态

本轮不增加实验、不修改运行时、不改配置或 checkpoint schema。Stage 3C-33 仍为最新冻结结果，Stage 3C-34 仍是下一唯一主线实验。

## 治理结论

以后每轮必须先声明任务类型和 Git 标题。只有验证并冻结后的结果才能进入 `docs/results/`；当前架构、活跃问题和当前进度分别只进入对应活动文档，禁止复制同一实验叙事到多份长期文档。
