# v0.128 D1-Z：主体图 Stage 3C-14 固定 Bootstrap 参数族可达性审计

## 1. 本轮问题

Stage 3C-12 表明把 branch horizon 从 5 延长到 8 tick 没有增加离散动作跨界；Stage 3C-13 表明把临时参数作用期从约一个后续 semantic activation tick 延长到约两个，会增加连续 action-potential 与 sampled-probability 差异，但仍未增加跨 source 的离散分化。与此同时，Stage 3C-10 至 3C-13 的所有 proposal 和 commit 都只到达 `node_bias`。

本轮因此不再同时扩大实体数、horizon、delta 或 exposure，而只检验一个更窄的问题：

> 在保持 source、候选寻址、eligibility、bounded delta、作用期、回滚和客观评估合同不变时，把固定 bootstrap 的 one-hot target-family 路由到另一个通用参数角色，是否改变短期更新可见性？

该问题只属于 fixed-cognition engineering baseline 的可达性审计，不是价值、效用、学习或主体性判断。

## 2. 单变量设计

正式比较：

```text
baseline:    node_bias        / thought-token port 23
alternative: node_output_gate / thought-token port 25
```

保持不变：

```text
independent sources:       9
seeds:                     12301..12309
entities/source:           32
bootstrap subjects/source: 16
source tick:               2
branch horizon:            8
rollback/control horizon:  3
backend:                   CPU
bounded delta:             unchanged
bootstrap topology size:   unchanged
permanent retention:       disabled
```

两个 target control 坐标都不参加 normalized-token association similarity。相同 graph activation 只把 one-hot target coordinate 从 port 23 移到 port 25；同一个 pre-activation local eligibility carrier 继续绑定同一个节点，不修改 association delay、candidate selector、proposal magnitude 或 rollback contract。

## 3. 预实验否决：node_input_gate

最初考虑把 `node_bias` 与 `node_input_gate` 比较，但三 source 探针发现两 arm 的连续差异、离散动作和客观窗口逐项相同。检查 bootstrap graph 后确认，目标节点读取的输入端口是恒为 1 的 `constant-one`，因此在这个固定图中：

```text
bias + delta
```

与

```text
(input_gate + delta) * constant_one
```

在目标计算处代数等价。

该 arm 因而在正式研究前被否决。这个结果只说明当前 bootstrap 构造使两个作用点退化等价，不说明两个参数族在一般图结构中等价。

## 4. 隔离合同

每个 seed 都在 bootstrap 前保存 source checkpoint。Stage 3C-14 assessment 必须验证：

1. 两 arm 的 pre-bootstrap state hash 与 config hash 相同；
2. stable subject 选择相同；
3. bootstrap profiles 只允许 target family 和 target token port 不同；
4. read-only control 的 action potential、sampled probability、action、resolution 和 objective event 完全一致；
5. thought token 只允许把同一个 target weight 从 port 23 搬到 port 25；
6. control 侧 token、association、eligibility 上游漏斗一致；
7. 两 arm 分别只向被授权参数族 proposal/commit；
8. Stage 3C-7、Stage 3C-8 和 Stage 3C-10 的统计层级与完整性门不变。

任何 source/config 漂移、寻址变化、额外 token 差异或未授权参数族写入都会使比较失败。

## 5. 正式九 Source 结果

两个 arm 的工程覆盖完全一致：

```text
proposals:                    722 / 722
live commits:                 144 / 144
completed paired windows:     141 / 141
pairing coverage:             1.0 / 1.0
rollback failures:            0 / 0
objective fact clipping:      0 / 0
evaluation cost match:        true / true
exact parameter restoration:  9/9 / 9/9
stable objective coordinates: 0/21 / 0/21
```

短期可见性不同：

| 指标 | `node_bias` | `node_output_gate` |
|---|---:|---:|
| action-potential difference events | 423 | 287 |
| sampled-probability difference events | 426 | 291 |
| discrete-action difference events | 2 | 1 |
| sources with discrete divergence | 1/9 | 1/9 |
| sources with objective-event divergence | 1/9 | 1/9 |
| stable objective coordinates | 0/21 | 0/21 |

`node_output_gate` 比 `node_bias` 少 136 次 action-potential 差异和 135 次 probability 差异，说明参数角色确实改变当前固定图中的短期连续可见性。然而，两 arm 都只在 1/9 source 出现离散/客观分化，且都没有稳定客观坐标。

## 6. 允许与不允许的解释

允许：

- fixed-bootstrap 参数族路由是当前短期可见性的实质因素；
- `node_bias` 与 `node_output_gate` 在这个固定图中不是代数等价作用点；
- 开放第二个可达参数族并不会自动产生跨 source 稳定客观方向；
- 需要继续把 bootstrap shaping bias 与一般认知结构主张分开。

不允许：

- 把较多连续差异解释为“更好”；
- 把较少离散 crossing 解释为“有害”；
- 给 energy、integrity、knowledge、relation 或任一参数族赋固定价值；
- 宣称信用分配正确、已形成学习或主体性；
- 自动保留任何参数；
- 因本轮结果改成统一 scalar reward；
- 将 fixed one-hot family route 写成唯一理论架构；
- 立即切换完整通用注意模型或拓扑演化。

## 7. 工程实现

新增能力位于外部 study/analysis 层：

- short paired runner 支持显式 `bootstrap_target_family`，默认仍为 `node_bias`；
- bootstrap profile 固定记录 family、token port、fixed-cognition shaping 标签和空 value semantics；
- source 在 bootstrap 前额外保存可校验 checkpoint，用于跨 arm 身份锚定；
- Stage 3C-14 assessment 校验 source、subject、token relocation、read-only behavior 和上游 funnel 隔离；
- 新增 protocol、workflow、CLI、单元测试和文档。

运行时没有新增第二套 checkpoint、branch、ledger 或生命周期系统，没有新增逐 tick 长期路径记录，也没有改变旧 checkpoint schema。默认 `node_bias` 配置身份和旧 checkpoint 加载行为保持兼容。

## 8. 下一边界

本轮已经说明“参数族作用点”影响可见性，但未产生稳定方向。下一步不应同时改 family、delta、horizon、exposure 或 topology。应先利用现有结果审计固定 bootstrap 中：

- 为什么 target-family 信号始终 one-hot；
- 六个参数族中哪些在当前节点/边结构上存在代数退化或近零灵敏度；
- 是否能在不引入价值语义、不改变 association selector 的前提下，对参数族局部灵敏度做外部、可替换、有限差分式工程诊断。

在该诊断完成前，不授权永久写入、自动 keep/revert、完整通用注意模型、拓扑演化或 Epoch 1 panel。
