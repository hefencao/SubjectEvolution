# v0.118 D1-Z：主体图 Stage 3C-4 受保护实时写入与短窗口回滚

## 本轮边界

本轮在 v0.117 影子事务之后增加第一条真实参数写入路径，但该路径仍属于工程安全实验：默认关闭、必须显式 opt-in、预算极小、写入有界并在固定短窗口后自动回滚。

本轮不判断更新是否有益，不定义 reward、valence、utility 或客观事件的固定正负意义，不开展 Epoch 1 实验。

## 已实现

- 新增 `src/se/subject_vm/live_write.py`；
- Stage 3C-4 独立 schema 与 `live_write.enabled` 显式开关；
- 仅接受 prepared 且 rollback-verified 的 Stage 3C-3 事务；
- 写入前再次执行 stable-target 与 exact float32 CAS；
- 同一事件 all-or-none 提交；
- 固定容量 per-subject applied ledger；
- pending transaction 数量、窗口目标数和窗口绝对 delta 预算；
- 禁止对仍 pending 的稳定目标重叠写入；
- rollback due tick 到达时在 activation 前执行 post-value CAS 和 all-or-none 回滚；
- 回滚异常时锁定该主体后续写入；
- commit/rollback count-only 成本；
- birth、death、compaction、clone、checkpoint 与 v0.117 checkpoint 升级；
- Stage 3C-4 `enabled=false` trajectory-neutral control。

## 未实现

- 根据行为或客观状态判断 keep/revert；
- 永久跨窗口参数保留；
- reward、主观价值或固定事件 polarity；
- 实体能量中的可塑性成本扣除；
- topology、retained state 或 eligibility 的事件驱动写入；
- GPU Stage 3 执行；
- 通用注意分配器替换 bootstrap 内容寻址；
- Epoch 1、主体性评分或涌现结论。

## 因果和安全顺序

```text
Stage 3C-2 bounded delta
→ Stage 3C-3 shadow CAS/apply/rollback proof
→ Stage 3C-4 second live CAS
→ fixed applied ledger
→ short live window
→ exact pre-activation rollback
```

任意检查失败都保持未提交。回滚失败不做局部修复，而是记录失败并锁定该主体写入路径。

## 科学证据边界

v0.118 只能证明候选更新可以在 live graph 中短暂、受限、可审计地存在并在正常条件下精确回滚。它不证明候选具有真实因果性、改善了行为、形成了价值或构成了学习。

## 后续授权边界

下一步如继续，应冻结 Stage 3C-5 keep-or-revert evaluation contract。必须保留强制回滚对照，明确评价窗口和干预原则，且不得把单一客观状态变化直接写成固定价值函数。
