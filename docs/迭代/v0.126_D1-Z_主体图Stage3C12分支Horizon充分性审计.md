# v0.126 D1-Z：主体图 Stage 3C-12 分支 Horizon 充分性审计

## 1. 决策

v0.125 已把独立 source 从 3 扩展到 9，确认 32 个实体、16 个 bootstrap subject 和 111 个窗口都不能替代独立 source，但仍未回答五 tick 是否过早停止。v0.126 选择一个变量：把 branch horizon 从 5 延长到 8 tick。

保持不变：

- seeds `12301..12309`；
- 每 source 32 个初始实体；
- 16 个 fixed-bootstrap subjects；
- source tick 2；
- CPU backend；
- association、eligibility、proposal、target binding、bounded update、shadow transaction、rollback、evaluation 和 export contracts；
- trace capacity 与 retention；
- permanent retention disabled；
- 主聚合层级 `window -> stable subject -> independent source`。

八 tick 是当前 `trace.retention_ticks=8` 下能够从 final checkpoint 完整观察整个分支事件范围的最大 horizon。本轮没有为了延长实验而扩大 trace、写入逐 tick 完整路径或增加第二套诊断生命周期。

## 2. 新增分析合同

新增 `se.analysis.subject_vm_stage3c12_horizon_adequacy` 和 CLI：

```text

```

分析器在比较结果前必须验证：

1. 两个 study 都通过 Stage 3C-7 工程筛查；
2. Stage 3C-8 与 Stage 3C-10 checksum 与 study identity 一致；
3. 除 `horizon_ticks` 外所有 study 因素完全相同；
4. seed panel、source checkpoint state hash 和 bootstrap lineage 逐 seed 相同；
5. 两个 arm 的 Stage 3C-10 divergence trace coverage 全部完整；
6. 五 tick 停止边界之前，guarded-live 和 read-only-control 的所有 event-shaped trace 数组逐 stable subject、逐 event tick 完全一致。

第 6 条用于证明八 tick arm 是五 tick trajectory 的真实延长，而不是另一次不同起点、不同随机路径或配置漂移的运行。checkpoint 文件实例哈希可以因创建时间不同而变化，但 source semantic state 和前缀事件必须一致。

```text
                                    horizon 5   horizon 8
```

```text

```

一个已经在五 tick 边界前发生 action 分化的 source，在后续 tick 中继续产生更多 objective-state difference。这是既有非参数路径依赖的延续，不是后续写入又跨过新的离散 action boundary。

## 6. 诊断解释

本轮支持：

- 五 tick 是有效工程探针，已经捕获当前九 source panel 中所有观察到的离散 action crossing；
- 延长到当前最大 trace-safe horizon 会完成更多窗口，但不会让稀疏离散 action 信号变得更密集；
- 单纯“再等三 tick”不是当前 3/144 commit 仅产生 3 次离散 action 差异的主要解释；
- branch horizon 控制观察长度，`rollback_after_ticks` 控制一次临时参数实际作用长度，二者不同；
- 当前每次 commit 仍只影响一个后续 semantic activation tick，temporary exposure duration 仍是未检验变量。

本轮不支持：

- 五 tick 对所有未来机制、环境或延迟普遍充分；
- 更新有效或无效的最终判断；
- stable learning、正确 causal credit 或主体性；
- permanent retention、automatic keep/revert 或 scalar objective；
- fixed nearest-token、single-winner target 或 bootstrap graph 是通用注意力或自然演化结构。

## 7. 下一边界

下一轮允许保持九 source、32 entities、8 tick trace-safe horizon、bounded delta 和 fixed bootstrap topology 不变，只比较一个 temporary parameter exposure duration 变量，例如将 rollback duration 从 2 调整到一个仍满足 trace/evaluation 合同的短值，并同步保持 control horizon 的合同一致。

不得把 exposure duration、delta scale、entity count 和 bootstrap topology 同时改变。若 exposure 对照仍不能增加跨 source 离散分化，再考虑固定 bootstrap 参数族可达性，而不是直接开启永久保留、长程大规模运行或切换完整通用注意模型。
