# v0.121 D1-Z：主体图 Stage 3C-7 配对证据充分性与完整性

## 本轮目标

在 v0.120 的共享 checkpoint 分支与 score-free paired export 之外，建立外部证据完整性筛查。该阶段只判断 paired evidence 是否具备继续分析的工程条件，不判断参数更新是否有益，不生成 objective scalar、keep/revert 或永久写入授权。

## 已实现

- 新增 `src/se/analysis/subject_vm_paired_evidence.py`：
  - 验证 Stage-3C-6 export checksum；
  - 验证引用的 guarded-live/control checkpoint 文件与 state hash；
  - 支持一次输入多个独立 shared-checkpoint pair；
  - 统计独立 source state，并显式报告重复 source；
  - 报告 paired、unpaired-live、unpaired-control 和覆盖率；
  - 对未配对记录分类：稳定主体缺失、source-event 分化、窗口边界分化、target/update 合同分化等；
  - 检查 rollback failure、pending write、locked row；
  - 报告 objective fact clipping 数量和比例；
  - 检查成对窗口的 evaluation count-only cost 是否一致；
  - 逐分量报告 alive entity/primary subject 身份重合、实体状态和环境字段分化；
  - 输出明确的工程筛查结果，但不授权科学充分性。
- 新增命令：

```bash
se-subject-vm-paired-evidence \
  --export pair_a/paired_evaluation_export.json \
  --export pair_b/paired_evaluation_export.json \
  --export pair_c/paired_evaluation_export.json \
  --output paired_evidence_assessment.json
```

- 默认筛查参数：
  - 至少 3 个独立 source checkpoint pair；
  - 至少 1 个配对窗口；
  - pooled pairing coverage 至少 0.80；
  - fact clipping fraction 不超过 0.05；
  - rollback failure 为 0；
  - paired evaluation count-cost 完全匹配。

这些参数均可通过 CLI 覆盖，并明确标记为工程筛查，不是普适科学阈值。

## 明确未实现

- objective coordinate weighting；
- scalar score、reward、utility、valence 或 polarity；
- 自动 keep/revert；
- 永久参数保留；
- 把 branch divergence 自动判定为收益或失败；
- 把同一 source checkpoint 的重复运行计为独立证据；
- 把窗口当作独立 biological replicate；
- 因果效应、学习、适应或主体性结论；
- 新的 Subject VM runtime/checkpoint schema；
- GPU Stage-3 分支执行。

## 科学证据边界

v0.121 只能证明 Stage-3C-6 导出的 paired evidence 可以被重复验证、分类和完整性筛查。即使筛查通过，也只表示证据链没有明显结构缺口，不能说明候选更新方向正确或应该永久保留。

下一步应优先建立 component-wise reproducibility assessment：以独立 source checkpoint pair 为重复单位，逐坐标报告符号、分布和稳定区间，并避免窗口层伪重复。该阶段仍不得压缩成通用 scalar objective。
