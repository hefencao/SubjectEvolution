# v0.98 D1-R：GPU 延迟梯度与 Workflow 回归修复

## 本轮范围

本轮不继续环境参数调试，不新增环境机制，也不进行任何遗传审计。唯一任务是
修复 D1-R `structured-panel` 在 `backend=auto` 选择混合 GPU 后的执行失败，并
恢复完整 `make test`。

用户现场错误发生在 tick 60：GPU policy preparation 没有返回主机侧资源梯度，
而同一 tick 后半段死亡或关系拓扑变化使 adaptive group refresh 突然变为 due，
CPU 分组阶段因此抛出：

```text
RuntimeError: GPU step omitted required resource gradients
```

## 根因

GPU prepare 只根据 step 前的 `group_update_due()` 判断是否提前下载资源梯度。
但 group refresh 的资格会在同一 tick 内发生变化：

1. GPU 已在设备上计算并使用资源梯度；
2. CPU 完成 action settlement；
3. 死亡、失效关系或关系更新把 group topology 标记为 dirty；
4. adaptive 最小刷新间隔已满足，group refresh 在 step 后半段变为 due；
5. 设备梯度仍存在，但旧接口没有保留可按需下载的引用。

这不是 workflow 参数错误，也不应通过把 `backend` 改成 `cpu` 来绕过。

## 修复

`HybridGpuRuntime` 现在保存当前 prepare pass 已计算、已包含氧气增强的设备资源
梯度。若 CPU commit 后半段发现 group refresh 变为 due，而 prepare 没有提前
下载主机副本，则调用：

```text
download_prepared_resource_gradient()
```

该调用：

- 下载与 policy 同一时刻、同一语义的梯度；
- 计入 GPU device-to-host transfer telemetry；
- 只在真实 late refresh 时发生；
- 不从可能滞后的 CPU 环境场重新计算；
- 不让所有 GPU tick 无条件多传两条实体向量；
- 不改变 CPU 路径。

每个 GPU step 开始时都会清除上一 tick 的保存引用；无 active entity 时也不会
保留陈旧梯度。

## `make test` 修复

首次实现把辅助逻辑加入 `runtime/sim.py`，使文件达到 2515 行并触发既有架构门：

```text
assert len(runtime/sim.py) < 2500
```

本轮没有放宽阈值。延迟梯度状态与下载逻辑保留在 `gpu_runtime.py`，`sim.py`
只保留最小按需调用，并清理冗余空行，最终为 2499 行。

新增回归覆盖：

- 当前 step 的设备梯度可以在 late group refresh 时按需下载；
- 两个梯度分量均保持 `float32` 数组语义；
- 下载字节进入 D2H 统计；
- 缺少当前 step 梯度时明确拒绝，而不是复用旧状态；
- 原架构门继续通过。

## 科学边界

本轮不改变：

- D1-R 四资源省区、加工省区、互补配方或原料交换参数；
- group 与分工候选标准；
- 正式 seeds 和 tick；
- genome、mutation、cost、reproduction；
- 单 seed 仅用于环境调参的规则；
- 禁止单轮遗传审计的授权边界。

用户此前失败的 panel 不可续接；应用补丁后应清理该不完整 panel 目录并从三个
正式 seed 重新运行。
