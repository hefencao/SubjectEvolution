# v0.117 D1-Z：主体图 Stage 3C-3 原子影子事务与回滚验证

## 1. 本轮目标

在 v0.116 的有界安全候选 delta 上建立 exact compare-and-swap、同事件 all-or-none、影子 apply 和 rollback 验证合同。仍不授权永久参数写入，不把事务通过解释为学习成功。

## 2. 已实现

### 2.1 精确 CAS

每个候选目标重新核验 stable ID、slot、表达状态和参数族。live 参数与 proposal 保存的 expected current value 必须具有完全相同的 float32 位表示；任意不一致都会拒绝该目标并中止整个事件事务。

### 2.2 同事件 all-or-none

一个客观事件产生的全部有效参数族候选被视为单一事务。任意目标 stale、CAS mismatch、projected value 不一致、非有限或超过目标数上限时，已经通过检查的其他目标也会被标记为 transaction-aborted，不允许部分提交。

### 2.3 影子 apply 与 rollback

通过检查的 projected values 只进入本次调用的固定六维私有影子向量。随后影子值恢复为 captured current values，并验证 float32 位级一致。`SubjectVMStorage` 始终只读。

### 2.4 计数型成本

事务保存 base cost units 与 per-target cost units 的计量结果。该数值只用于未来成本建模和比较，不扣实体能量，不影响行动，也不消耗随机数。

### 2.5 生命周期

影子事务结果随 event ring 参与 clone、checkpoint、compaction 和 death 清理。birth 不继承父代事件历史。v0.116 checkpoint 升级时建立空事务元数据，不伪造已应用更新。

## 3. 明确未实现

- live graph parameter write；
- permanent commit；
- live rollback 或 partial-write recovery；
- applied-update long-window ledger；
- physical plasticity cost debit；
- eligibility、retained state 或 topology 写入；
- 学习效果、适应性或主体性结论。

## 4. 科学边界

本轮只能证明：

> Stage 3C-2 候选能够在 live graph 保持只读的前提下，经 exact CAS、all-or-none、shadow apply 和 exact rollback 形成可恢复事务证据。

不能证明候选具有因果正确性，也不能证明真实参数写入安全或有效。

## 5. 下一授权边界

下一阶段如继续，应先冻结 Stage 3C-4 guarded live-write experiment：默认关闭、显式 opt-in、极小更新预算、applied ledger、短窗口 rollback、count-only cost 和 trajectory-neutral control。不得直接把影子事务改成无保护永久写入。
