# v0.99 D1-R：历史边界与发布归档回归修复

## 本轮范围

本轮仅修复本地保留历史资料时的 `make test` 与完整项目归档行为，不修改
D1-R 环境、主体、GPU 执行、正式 seeds、运行 tick 或科学资格门。

## 根因

部分治理测试把完整发布包的清洁约束错误地施加到用户本地工作树：

- 扫描 `docs` 下所有历史 `v0.*` 路径；
- 扫描 `docs/迭代` 内旧版本 README 的命令块；
- 扫描已退休 study 中遗留的 `commands/*.sh`；
- 归档器只删除旧迭代文件，没有删除旧迭代目录。

这违反项目既有规则：本地允许保留全部历史，补丁不得删除历史；只有临时发布副本
必须只保留当前版本迭代文档。

## 修复

- 当前迭代文档测试只约束当前项目版本必须位于 `docs/迭代/`，不再因旧版本
  历史布局失败。
- README 命令去重检查排除 `docs/迭代/` 及早期 `docs/v0.xx/` 历史区。
- 声明式 workflow 检查只约束实际拥有 `workflow.toml` 的 study，不再扫描已退休
  legacy study。
- 项目归档器在临时副本中同时删除 `docs/迭代/` 的非当前版本文件/目录，以及早期 `docs/v0.xx/` 资料树；源工作树不变。
- 新增隔离 fixture，验证归档后只保留当前迭代文档，同时历史文件和目录仍存在于
  原项目中。

## 科学边界

本轮不改变任何科学状态。D1-R 仍以结构化资源网络、群体内持续功能分化和多个
独立 seed 的结构门为当前主线；禁止单轮遗传审计的规则保持不变。
