# v0.119 D1-Z：主体图 Stage 3C-5 受保护客观评估窗口

## 本轮目标

在 v0.118 的短窗口实时写入与强制回滚上增加一个固定容量、可 checkpoint 的客观评估窗口。评估窗口用于后续 paired branch 或独立对照分析，不在主体内部生成单一分数，也不决定更新是否保留。

## 已实现

- `src/se/subject_vm/evaluation.py` 独立拥有评估窗口和生命周期；
- 同一 Stage 3C-5 合同支持：
  - `live_write.enabled=true` 的 guarded-live 臂；
  - `live_write.enabled=false` 的 read-only control 臂；
- 窗口从候选事务事件之后开始，只观察未来 tick；
- guarded-live 窗口只有在到期精确回滚后才标记完成；
- control 窗口按相同 horizon 完成且从不修改参数；
- 每窗口保存 21 维客观事实的逐维累计、绝对累计和最大绝对值；
- 保存观察数量、动作成功/失败数量、裁剪数量、目标族、稳定目标、pre/projected 值和 bounded delta；
- 记录回滚完整性和窗口结束后的写入锁定状态；
- birth 清空窗口，death 释放，compaction 跟随稳定所有权，clone/checkpoint 精确保存；
- v0.118 checkpoint 在 Stage 3C-5 配置下安全重建空评估 ledger；
- 注册与观察成本只计数，不扣实体能量。

## 明确未实现

- 将多维客观事实压缩成 reward、utility、valence 或单一质量分数；
- runtime 内部自动比较 live 与 control 并给出因果结论；
- 自动 keep/revert 决策；
- 回滚后永久保留参数；
- 根据窗口事实再次调制 eligibility、参数或拓扑；
- paired branch 正式实验；
- GPU Stage 3 执行；
- Epoch 1 或主体性结论。

## 因果顺序

```text
prepared transaction
→ guarded-live 或 read-only control 窗口注册
→ 只观察后续客观事件
→ 保存逐维、无权重的客观证据
→ guarded-live 精确回滚 / control 同 horizon 完成
→ 外部分析以后再比较
```

当前窗口不构造自动反事实。真实因果比较仍需要共享 checkpoint、预注册 paired branch 和成本匹配设计。

## 科学证据边界

v0.119 只能证明实时臂与只读臂能够用同一固定数据合同保存有界、无分数的客观窗口证据，并且实时臂的证据只在回滚完整后完成。它不能证明候选更新有效、有益、具有主观价值或应被永久保留。
