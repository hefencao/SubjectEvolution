# v0.125 D1-Z：主体图 Stage 3C-11 独立 Source 样本充分性审计

## 1. 决策

v0.124 已说明三 source、五 tick 研究的数据链真实运行，但连续参数影响通常没有跨过离散动作边界。用户进一步质疑 32 实体和五 tick 是否构成有效样本。本轮不把实体、主体或窗口误算成独立重复，也不同时改变实体数和 horizon；选择唯一变量：把独立 source checkpoint 从 3 个扩展到预声明的 9 个。

保持不变：

- 32 个初始实体；
- 16 个 fixed-bootstrap subjects；
- source tick 2；
- branch horizon 5；
- CPU backend；
- bounded delta、rollback、evaluation 和 control reservation 合同；
- export-boundary finalization；
- permanent retention disabled；
- 主聚合层级 `window -> stable subject -> independent source`。

第一批 seeds `12301..12303` 是 pilot prefix，新增 `12304..12309` 的零结果与非零结果全部保留。

## 2. 样本含义

32 个实体是每个 source 内的生态状态规模，不是 32 个独立统计样本。16 个 bootstrap subject 和多个窗口也是 source 内嵌套观测。当前最高独立重复单位是由独立 seed 生成、具有不同 source-state hash 的 checkpoint。因此：

- 原研究独立 `n=3`；
- 本轮独立 `n=9`；
- 111 个完整窗口不能被表述为 `n=111`；
- 更多窗口可以改善 source 内估计，但不能制造更多独立历史。

五 tick 对工程验证是有效的：它会产生候选、临时写入、完成窗口、精确回滚和少量分支分化。但它还不能证明足以捕获全部延迟效应，更不能代表长程生态分布。

## 3. 实现

新增 `se.analysis.subject_vm_stage3c11_sample_adequacy`：

- 验证 study、Stage 3C-8 和 Stage 3C-10 checksum；
- 锁定 source state 为最高重复单位；
- 对 source prefix `3..9` 重算窗口数、非零 source、Stage 3C-8 描述性稳定坐标；
- 报告离散 action 分化、trace objective-event 分化和完成窗口非零向量的 source incidence；
- 为稀疏 source incidence 提供描述性 Wilson 95% 区间；
- 明确区间不是显著性、功效、价值或永久保留授权。

Stage 3C-10 同时修正两个诊断边界：

1. paired admission/evaluation symmetry 与干预后的 transaction preparation path equality 分开。前者必须对称；后者在 live 分支已改变未来内部路径后不要求相同。
2. 分支时间线报告 trace tick coverage。若 horizon 超过有界 ring 可保留范围，计数标为 lower bound，不能把覆盖后的早期差异当成完整零。

没有新增运行时状态、checkpoint schema、第二套 ledger/branch owner 或无界历史。

为验证跨运行可重复性，报告同时保留单次 artifact checksum 与 semantic-result hash。前者绑定含 `created_utc` 的具体 checkpoint/plan/export 文件，重复生成时允许不同；后者绑定 source state hash、参数、逐分量统计和科学边界，排除路径、创建时间和 ZIP 容器元数据。两次相同运行的 Stage 3C-10 JSON 和 Stage 3C-11 semantic-result hash 一致。

## 4. 真实九 source 结果

固定参数 study：

```text
seeds: 12301..12309
initial entities: 32
bootstrap subjects: 16
source tick: 2
branch horizon: 5
backend: CPU
permanent retention: disabled
```

工程完整性：

```text
independent source pairs = 9
completed paired windows = 111
pairing coverage = 1.0
rollback failure = 0
objective fact clipping = 0
evaluation cost match = 1.0
paired admission contract pass = 9 / 9
```

样本敏感性：

```text
pilot prefix (3 sources): 38 windows
trace action/objective divergence = 1 / 3
nonzero completed-window objective vector = 1 / 3
stable objective coordinates = 0 / 21

expanded panel (9 sources): 111 windows
trace action/objective divergence = 2 / 9
nonzero completed-window objective vector = 1 / 9
stable objective coordinates = 0 / 21
```

描述性比例仍具有宽区间；它们说明当前效应稀疏，而不是证明真实发生率或零效应。

## 5. 诊断中发现的合同问题

没有发现实际 paired branch、reservation、rollback、finalization、lineage 或 hierarchical aggregation 错误。

新增 seeds 暴露的是旧诊断范围过宽：四个 source 在 live 参数已经改变后续内部路径后，shadow transaction preparation 数量与 control 不再相同。9/9 source 的 actual admission/control reservation、evaluation counted cost、窗口配对和回滚仍严格对称，因此这不是准入合同失败。诊断已修正并由测试覆盖。

探索性 horizon 16 检查还暴露最终 checkpoint 的有界 trace ring 会覆盖早期 tick。该运行只用于发现可观测性边界，不作为本轮科学比较；正式结果仍是 horizon 5 的单变量 source-count study。

## 6. 允许与不允许的结论

允许：

- 三 source pilot 是有效工程探针，但不足以支持跨 source 稳定方向；
- 九 source 面板仍显示参数到客观事件的转换稀疏；
- 32 实体和 111 窗口不能替代独立 source；
- 五 tick 可验证短程链路，但其延迟可见性充分性尚未成立；
- 下一轮可在九 source 控制下单独比较 horizon 或临时作用覆盖，但必须先保证 horizon-safe 观测。

不允许：

- 更新有效或无效的最终判决；
- 九 source 已达到通用科学充分性；
- 永久参数保留、自动 keep/revert 或 scalar objective；
- fixed nearest-token/single-winner 是通用注意力或自然演化结构；
- 稳定学习、因果信用正确性、主体性或 Epoch 1 成立。

## 7. 下一边界

下一版本应只选一个变量。基于当前证据，优先候选是 branch horizon 或临时参数实际覆盖 tick 数，而不是先扩大实体规模；前者直接测试“连续影响是否因观察/作用时间过短而未转成离散事件”。任何 horizon 对照必须保留五 tick 对照、九 source panel、无永久保留和原 Stage 3C-7/8 层级，并避免 trace ring 覆盖造成假零。
