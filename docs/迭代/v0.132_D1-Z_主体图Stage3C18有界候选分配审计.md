# v0.132 D1-Z：主体图 Stage 3C-18 有界候选分配审计

## 1. 本轮问题

Stage 3C-17 证明，当所有 normalized-dot similarity 都为 1.0 时，latest/oldest 时间并列规则会显著改变历史事件复用方式，但两端 single-winner 规则都没有产生跨 source 稳定客观方向。本轮不继续在时间端点之间摆动，而检验一个更小的变量：在保持 latest 排序、候选合法性和总更新预算不变时，每个当前事件最多选择一个还是两个历史候选。

问题被严格限定为：

> 第二个有界候选是否增加历史证据覆盖或短程写入可见性，而不引入 learned weight、价值语义、多次 proposal 或额外 update budget？

## 2. 不变量与唯一变量

九个独立 source 使用 seeds `12301..12309`。每 source 32 个实体、16 个 fixed-bootstrap subject、source tick 2、branch horizon 8、rollback/exposure 3、CPU。`edge_forward_gate` target、edge local eligibility carrier、latest-on-tie、normalized-dot similarity、threshold、delay bounds、bounded delta、shadow transaction、guarded live write、automatic rollback、Stage 3C-7/8/10 与 source-level replicate hierarchy 全部保持不变。

唯一变量：

```text
top-1: association_candidate_limit = 1
top-2: association_candidate_limit = 2
```

Top-2 将两个按现有规则排序的候选的 21 维 objective-fact vector 做等权均值，然后仍只形成一个 modulation proposal。单事件 delta budget、transaction 数上限和 write/window 生命周期没有扩大。

## 3. 实现

### 3.1 有界候选选择

`se.subject_vm.association` 保留现有 score 和 latest tie-break，只返回前一个或前两个通过门限的候选。默认 limit 仍为 1。Limit 2 只允许通过 checksum-bound paired-plan runtime override 启用，并同时施加于 live/control。

### 3.2 固定容量审计事实

Trace schema 从 v8 升级到 v9，在 association 启用时每个 `(entity, trace slot)` 增加：

- selected count：1 byte；
- secondary event ID：8 bytes；
- secondary event tick：8 bytes；
- secondary delay：4 bytes；
- secondary similarity：4 bytes。

总增长：

```text
25 × entity_capacity × trace_capacity_per_subject bytes
```

不随 node/edge capacity 增长。旧 checkpoint 的 primary assignment 恢复为 selected count 1，secondary 字段为空；默认运行和旧 config identity 不变。

### 3.3 外部分析

新增 Stage 3C-18 analyzer，核验：

- source state/config 和 bootstrap subject identity；
- read-only control event arrays；
- tie-break、delay、threshold、family、carrier、delta/update budget；
- top-1/top-2 只改变 candidate limit；
- candidate reference 数、delay histogram、unique event coverage 与 reuse concentration；
- Stage 3C-7/8/10 工程和分量证据。

窗口仍不是独立重复，最高重复单位仍为 independent source checkpoint。

## 5. 历史覆盖与复用

Top-1 的 1008 个候选全部为 delay 1。每 source 使用 112 个唯一历史事件，每个事件只使用一次。

Top-2 保留全部 primary delay-1 引用，并为 864 个事件增加 delay-2 secondary reference。但每 source 的唯一历史事件仍为 112，没有新增覆盖；其中 96 个历史事件改为被使用两次，maximum reuse 从 1 增至 2。

因此第二候选增加的是引用数和已有事件的聚合权重，不是新的历史事实覆盖。

## 6. 允许与禁止的解释

允许：

- candidate limit 是 fixed-bootstrap addressing 的实质因素；
- top-2 会改变 proposal、连续差异和 completed-window 数；
- 当前 top-2 没有增加 unique event coverage 或 commit；
- 两个 arm 都没有跨 source 稳定客观坐标。

禁止：

- 把 top-2 或 top-1 描述为更好；
- 把 equal weight 描述为 learned attention；
- 把更多 proposal/window 描述为学习；
- 把更少 discrete crossing 描述为有害；
- 授权永久 retention、reward、utility、trust 或 scalar objective；
- 将 normalized-dot top-k 宣称为通用注意力。

## 7. 下一边界

所有 selected similarities 仍为 1.0，而 top-2 只增加重复引用。这表明继续增大 top-k 或增加固定/学习权重之前，应先从外部分析 token geometry 的可分辨性：

- association-visible coordinate variance；
- covariance effective rank；
- pairwise normalized-dot score spread；
- threshold margin；
- query/candidate 重复率。

该诊断应保持九 source、runtime、候选选择、参数族、carrier、delta 和回滚完全不变。只有真实数据证明 token score 具有可分离结构后，才考虑新的候选 allocator 比较。
