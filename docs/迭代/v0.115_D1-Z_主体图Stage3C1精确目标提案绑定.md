# v0.115 D1-Z：主体图 Stage 3C-1 精确目标提案绑定

## 1. 本轮目标

本轮继续沿用 v0.113/v0.114 已冻结的单候选连续 token 寻址与参数族调制提案，先完成可审计的具体 target proposal binding，不切换到完整通用注意模型，也不执行任何参数写入。

已有 normalized-dot 单候选寻址和本轮单赢家资格选择被明确定位为 **bootstrap bias / 固定工程基线**：它们用于缩短早期网络塑形与调试路径，不代表项目认定其为唯一或最终注意机制。未来可以在同一统一图边界内替换或增加更通用的候选评分、预算分配和惰性载荷执行模型。

## 2. 已实现

### 2.1 激活前历史资格候选

Stage 3C-1 在每个激活 tick 中按以下顺序处理：

1. 对节点/边局部 eligibility 按经过 tick 衰减与到期；
2. 在当前 tick 节点/边执行和新 eligibility mark 之前，生成紧凑候选；
3. 每个六维参数族最多保留一个候选；
4. 完成当前激活并产生新的局部 eligibility；
5. 世界提交后，只有已产生的 Stage 3B-3 参数族提案可以尝试绑定预先保存的候选。

因此当前行动刚产生的资格不能成为该行动后果的历史目标。候选 age 必须大于零；同 tick 新 mark 会被保守拒绝。

### 2.2 Bootstrap 单赢家选择

候选选择使用固定、确定性的工程基线：

- 必须是 expressed 且具有 local eligibility flag 的节点或边；
- 绝对 eligibility 不低于配置阈值；
- node-input/output/trace-gate 族还要求对应端口已接线；
- 按绝对 eligibility 最大者选择；
- 并列时选择更小的稳定 node/edge ID；
- 每个参数族最多一个 target；
- 允许没有 target。

这不是完整通用注意模型，也不是主体性结论。

### 2.3 持久化内容

每个已提交事件最多保存六个有界 target proposal：

- target family 是否请求和是否成功绑定；
- 角色中性拒绝原因；
- node/edge target kind；
- 固定槽位 index 与稳定 node/edge ID；
- 激活前局部 eligibility 值；
- 原始参数族 proposal component。

不保存整张 eligibility 数组、节点/边执行路径、激活掩码或当前 tick 全部候选。

## 3. 明确未实现

本轮没有：

- 把 family proposal 与 eligibility 相乘为最终 delta；
- 参数裁剪、累计预算、rollback 或稳定性检查；
- node bias、gate、bandwidth、retained state 或 topology 写入；
- 物理 plasticity 成本扣除；
- 自动突变或发育表达；
- 通用候选评分、Softmax、Top-K、多头注意或 QKV 合同；
- Epoch 1、主体性或涌现实验。

## 4. 生命周期与兼容

- pending target candidates 只在 activation→objective commit 的瞬态阶段存在；checkpoint 和 clone 禁止跨未提交阶段进行；
- committed binding metadata 随 trace ring 参与 clone、checkpoint、compaction 和 death 清理；
- birth 的 graph structure 可以继承，但 trace/binding 历史为空；
- v0.114 Stage 3B-3 checkpoint 恢复为同一图与 proposal 状态，并新建空 binding metadata；
- disabled target-binding 配置继续从 canonical identity 中移除。

## 5. 科学边界

本轮只能证明：

> 已有参数族提案可以在不保存长期微观路径、且不混入当前 tick 新资格的条件下，绑定到有限、仍有效的具体局部载体。

它不能证明候选具有因果性，不能证明绑定方向正确，也不能证明已经发生学习。

## 6. 下一授权边界

下一阶段应单独冻结 Stage 3C-2 update-safety proposal：

- 如何由 family proposal、局部 eligibility 和参数当前值生成可拒绝的候选 delta；
- 每参数、每 tick、每主体和长窗口累计边界；
- stale target ID/slot 再验证；
- rollback 与 checkpoint 原子性；
- count-only 成本账本；
- 仍不立即进入演化选择或 Epoch 1。
