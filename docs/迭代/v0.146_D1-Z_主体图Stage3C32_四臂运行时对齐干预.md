# v0.146 D1-Z：主体图 Stage 3C-32 四臂运行时对齐干预

## 1. 主线位置

`Stage 3C-31 只读主体—时间对齐消融冻结 → 3C-32 同路径 runtime alignment policy → 每 source 四臂共享 checkpoint → selector/update-route 因果分解 → 21 维 Objective-Fact difference-in-differences → 九 source 冻结`

本轮不引入 reward、learned weight、自动 keep/revert 或永久 retention。Stage 3C-32 的 runtime 变化只存在于实验显式覆盖中；默认配置与旧 checkpoint 仍使用 `native` 路径。

## 2. 单一问题

Stage 3C-31 已证明，第二 visible coordinate 与具体主体历史的绑定对离线 winner identity 有机械作用。但离线重打分不能证明该绑定在真实运行时会改变后续关联、临时参数写入路由和 Objective-Fact。

Stage 3C-32 因此检验：在共享 source checkpoint、相同运行时路径、相同候选机会、相同计算/存储成本和强制 rollback 下，保持或打断 port 30 的主体—时间对齐是否会因果改变：

1. selected historical event identity；
2. 临时 update target/family/delta 路由；
3. guarded-live 相对 read-only-control 的 21 维 Objective-Fact 结果。

## 3. 四臂隔离合同

每个独立 source 从同一个 Stage 3C-23 rank-two checkpoint 派生四个 branch：

- aligned / read-only-control；
- aligned / guarded-live；
- alignment-ablated / read-only-control；
- alignment-ablated / guarded-live。

两个 alignment mode 走同一稳定排序和坐标复制代码路径：

- aligned：`tickwise-subject-identity-v1`，donor 为自身；
- ablated：`tickwise-cyclic-subject-donor-v1`，donor 为同 tick 的其他主体，offset 随 tick 变化。

共同约束：

- 共享 checkpoint file/state/config identity 和 source tick；
- 固定 16 个 bootstrap subjects、8-tick branch horizon、3-tick temporary exposure；
- 固定 normalized-dot、threshold 0.8、latest/top-1、target/carrier、delta clip 和随机流；
- 每 tick 精确保留 port 30 的 float32 multiset；cyclic donor 不得为自身；
- 候选评估次数、alignment assignment 数和 runtime array bytes 必须匹配；
- guarded-live 必须 rollback，read-only-control 仍保持对称 reservation；
- Objective-Fact 只做逐坐标 live-minus-control，再做 `ablated - aligned` 的 source-balanced difference-in-differences；不生成标量。

## 4. 正式九 source 结果

### 4.1 操纵确实进入运行时链

九个 source 的 manipulation、cost/storage 和 rollback 合同均成立。port 30 对齐消融对 128 个可比较事件/每 source 的影响为：

- association identity 改变比例：32.03%–50.78%，中位数 46.09%；总计 518 次；
- update route 改变比例：9.38%–17.97%，中位数 14.06%；总计 156 次；
- bounded delta 内容改变：每 source 23–30 次，中位数 27；总计 243 次。

因此，主体—时间对齐不是只改变离线日志或重打分。它在该 fixed bootstrap 下因果决定了部分历史事件选择，并继续决定部分临时参数 target/family/delta 路由。

### 4.2 当前暴露不足以形成跨 source Objective-Fact 结果

aligned mode 得到 121 个完成 paired windows，alignment-ablated mode 得到 125 个。尽管 selector 和 update route 在 9/9 source 中都发生变化，只有 seed 12301 出现非零的跨 mode Objective-Fact difference-in-differences；其余 8 个 source 的 21 维事实差均为零。

因此：

- `sources_with_nonzero_componentwise_live_control_effect = 1/9`；
- 0/21 fact-sum 坐标具有跨九 source 稳定方向；
- 0/21 absolute-fact-sum 坐标具有跨九 source 稳定方向；
- 当前 3-tick exposure 不能支持 source-replicated Objective-Fact 因果结论。

该结果与 Stage 3C-10/11/23 的长期诊断一致：短 rollback 窗口内的临时参数变化能够改变内部路径，但多数 source 尚未跨越离散 action/objective-event 边界。这里的根因不是 manipulation failure，也不是候选/成本不匹配，而是下游 effect sparsity 与暴露长度边界。

## 5. 冻结解释

Stage 3C-32 支持两个窄因果结论：

1. 在当前 fixed bootstrap 下，port 30 的主体—时间对齐对 selector identity 有运行时因果作用；
2. 它对临时 update routing 有运行时因果作用。

Stage 3C-32 不支持：

- 对齐产生稳定或统一方向的 Objective-Fact 改善；
- 某个事实坐标具有固定价值；
- 当前 selector 是正确的 causal credit；
- 任何 learned weight、reward、自动 keep/revert 或永久 retention；
- 通用 attention 或主体性结论。

## 6. 轻量治理检查

- **数据与预期不符及根因**：如果预期四臂干预会在 9/9 source 形成 Objective-Fact 差异，则正式结果不支持。根因已分离为“内部 selector/update route 变化充分，但 3-tick temporary exposure 的下游事实效应稀疏”，而不是 manipulation、lineage、compute/storage 或 rollback 失败。因此当前任务不应通过放宽稳定阈值、选择 seed 或标量化来调整。
- **新长期原则**：没有新增通用科学原则。新增的是已写入协议的具体实验边界：运行时寻址干预必须同时有 identity manipulation、cost/storage match、forced rollback 和 component-wise difference-in-differences。
- **仅存在于聊天中的原则**：没有。用户对验证输出和交付聚合的要求写入交付/验证文档，不改变科学合同；Stage 3C-32 的设计、结果和下一步边界均已持久化。

## 7. 下一边界

下一步应单独声明 Stage 3C-33 exposure-length intervention，而不是在本轮追跑直到出现期望结果。它必须复用同一九 source checkpoint 与四臂结构，只改变 temporary exposure/horizon，并继续保持：

- 相同 alignment manipulation；
- 相同 candidate opportunity、compute/storage 和随机合同；
- 强制 rollback；
- 逐坐标、source-balanced、无 score 的 Objective-Fact 评估；
- 无自动 keep/revert 和永久 retention。

Stage 3C-33 的问题只能是：更长但仍受控的 temporary exposure 是否让已经成立的 selector/update-route 因果链传播到可重复的 Objective-Fact 差异。
