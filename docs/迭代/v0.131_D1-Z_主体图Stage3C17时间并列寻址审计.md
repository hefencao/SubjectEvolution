# v0.131 D1-Z：主体图 Stage 3C-17 时间并列寻址审计

## 目标

Stage 3C-16 已使 `edge_forward_gate` 在固定 carrier 上可达，但 Stage 3C-10/15 同时表明 bootstrap token 的 normalized-dot similarity 全部为 1.0，默认 selector 因并列规则总是选择 delay=1。v0.131 只比较 exact-similarity tie 时选择最新候选或最旧候选，判断短程信号是否被固定时间偏置主导。

## 单变量合同

固定九个独立 source、每 source 32 实体、16 bootstrap subjects、source tick 2、branch horizon 8、exposure 3、CPU、`edge_forward_gate`、edge local eligibility carrier、candidate delay bounds 1–6、normalized-dot similarity、threshold、bounded delta、自动回滚与 Stage 3C-8 层级。

唯一变化：

```text
latest eligible event on exact similarity tie
→ oldest eligible event on exact similarity tie
```

该策略作为 paired-plan runtime override 使用，不加入配置 schema，不改变旧 config identity，不增加 checkpoint 字段或持久内存。

## 九 source 结果

两个 arm 都产生 1008 次 assigned association，全部 similarity=1.0。

- latest：1008/1008 为 delay=1；每 source 关联 112 个唯一历史事件；单事件最大复用 1。
- oldest：delay 1–6，均值 3.857；每 source 只关联 32 个唯一历史事件；单事件最大复用 6。
- latest：942 proposals、144 commits、129 completed windows、4 次离散动作差异、3/9 source 客观分化。
- oldest：801 proposals、143 commits、105 completed windows、2 次离散动作差异、2/9 source 客观分化。
- 两个 arm 的 Stage 3C-8 都为 0/21 稳定客观坐标。

## 解释

默认 latest tie-break 确实是造成 delay=1 集中的固定 bootstrap 偏置。但 oldest 并没有提供更分散的历史覆盖，而是把集中方式改成对少数较老事件的重复复用。proposal 与窗口数量下降，不能解释为 oldest 有害，也不能把 latest 的更多分化解释为更好。

本轮只授权：时间并列规则会实质改变 association 分配和短程可见性。它不授权因果信用、价值、学习、永久保留或通用注意力结论。

## 实现与内存

新增外部分析器 `src/se/analysis/subject_vm_stage3c17_temporal_tie_break.py`、study workflow 和 decision protocol。运行时只增加一个非持久的字符串策略选择，默认仍为 `latest`；持久内存增长与 checkpoint 墤长均为 0。
