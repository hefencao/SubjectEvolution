# v0.85 D1-F：按资源通道分配的可遗传感知尺度

## 结果输入

D1-E 的三组共享 checkpoint 配对均满足注册合同，但保留统一遗传半径的分支在三个 seed 中分别少存活 55、40、114 个实体，平均能量也全部更低。tick 480 的四资源字段保持非平凡方差，但有效维度只有约 1.77–1.91，平均绝对通道相关约 0.60–0.64。

这说明持久多尺度环境没有解决统一感知半径的能力边界：扩大半径会同时平滑四个通道，主体无法在保留其他通道局部细节的同时远距读取其主要资源通道。

## 本轮实现

新增 `inherited-affinity-routed-gradient-radius-v2`：

- morphology gene 7 仍决定 1、2、4、8 的遗传 reach capacity；
- 已有固定预算 resource-affinity genes 决定哪个资源通道获得扩展半径；
- 其余三个通道保持 radius 1；
- affinity 并列时按最低通道索引确定性选择；
- 维护、使用和发育成本仍只由遗传 reach capacity 决定；
- `neutralize-resource-sensing-radius` 将全部有效通道半径中和为 1，但不改变基因、affinity、成本、资源场或共享 checkpoint。

没有增加奖励、角色标签或环境反馈。

## 工作流改造

study 操作不再存成可执行 `.sh` 文件。每个活跃 study 使用只读 `workflow.toml`，由 `se-study` 显示和执行：

```text
se-study show studies/d1f_channel_selective_resource_sensing_v1
se-study run studies/d1f_channel_selective_resource_sensing_v1 source-pilot --backend gpu --seeds 85001,85002,85003
```

runner 只接受 manifest 中声明的参数，输出完整 argv，并使用无 shell 的 subprocess 执行。`--dry-run` 可在执行前检查最终命令。

## 文档边界

本地 checkout 可在 `docs/迭代/` 保留任意历史迭代文档。`conda-sync` 只检查 pyproject、package 和 durable status 的版本一致性，不再检查或删除迭代历史。完整项目压缩包在临时副本中只保留当前版本迭代文档。
