# v0.151 工作区命令与工作流分级

- 类型：`[ENGINEERING]`
- Git 标题：`[ENGINEERING] workspace: separate configuration ownership and workflow profiles`
- 分支：`engineering/workspace-cli-workflow-profiles`
- 科学证据变化：无
- Subject VM runtime/checkpoint/config 变化：无

## 问题

根目录 `AGENTS.md` 把完整测试、Conda、补丁重放、归档和发布流程设为每次修改的
无条件要求，导致小修复也被迫伪装成完整发布。工作区目录设置同时挂在
`se-study config` 下，使研究 workflow runner 承担了无关的操作员环境职责。

## 修改

1. 新增 `docs/WORKFLOW_PROFILES.md`，区分 `SCOPED-FIX`、`STANDARD-CODE`、
   `SCIENTIFIC-FREEZE` 和 `RELEASE-HANDOFF`。
2. `AGENTS.md` 只保留跨任务不变量、分类、文档边界和 Git 输出合同，不再内嵌完整流程。
3. 新增独立 `se-workspace` 命令，负责 `.se-workspace.toml` 的查看、修改和路径输出。
4. `se-study` 只消费 result path 设置，不再暴露 `config` 子命令。
5. 自动判断“用户准备本地处理、无需打包”的策略暂不固化，作为 parked 工程治理项。

## 选择的工作流

本轮修改公共 console entry 和 `pyproject.toml`，因此使用 `STANDARD-CODE`；由于
仍需交付版本化项目包和补丁，再组合 `RELEASE-HANDOFF`。这不是以后小修复的默认流程。
