# v0.114 D1-Z：主体图 Stage 3B-3 有界调制提案

## 本轮定位

本轮在 v0.113 有界延迟关联候选之上，只实现**可拒绝、定长、参数族级别的调制提案**。提案不绑定具体节点或边，不写入 eligibility，不修改图参数，也不把客观事件解释为 reward、价值或极性。

核心边界：

> 关联候选只提供历史引用；图可以根据当前与历史的客观事实差生成一个通用调制提案，但引擎不得替图决定事件好坏，也不得把提案直接执行为参数更新。

## 已实现

### 配置与固定宽度合同

新增：

- `partitioned-subject-graph-vm-stage3b3-modulation-proposal-v1`；
- `bounded-objective-contrast-modulation-proposal-v1`；
- 一个 modulation request token port；
- 21 个客观事实投影坐标；
- 6 个通用参数族方向坐标；
- request threshold；
- proposal clip。

21 维客观事实仅由已记录的角色中性量组成：

- 12 维 objective state delta；
- 4 维外部资源变化；
- 4 维内部 raw store 变化；
- 1 维实际能耗。

六个参数族仅表示未来可能的通用目标类别：

1. node bias；
2. node input gate；
3. node output gate；
4. node trace gate；
5. edge forward gate；
6. edge bandwidth。

本轮没有把参数族解析成具体 node slot、edge slot 或 topology target。

### 图产生的事实投影与目标方向

连续 token 中的普通 readout 输出决定：

- 是否请求提案；
- 如何投影当前与历史客观事实差；
- 提案朝哪些通用参数族方向分布。

引擎只提供客观事实向量和有界归一化算子，不命名“伤害”“收益”“知识价值”“信任”或其他主观概念。

### 候选相似度与调制提案分离

所有 modulation 控制坐标均从 Stage 3B-2 的关联 query 和 candidate 中排除。因此：

- 增大提案请求值不能提高关联相似度；
- 改变事实投影权重不能改变关联候选；
- 改变参数族方向不能改变关联候选；
- association similarity 和 delay 不参与 proposal signal 或 proposal vector 的缩放。

这避免把“内部表征相似”偷换成“因果信用强度”。

### 可拒绝提案

只有在以下条件同时成立时才产生提案：

- 图明确请求；
- 当前事件已获得有效历史关联候选；
- 事实投影权重非零；
- 当前与历史的客观事实差非零；
- 参数族方向非零；
- 最终有界 signal 和 vector 非零。

否则保存明确的拒绝原因。当前提案只包含：

- 是否请求；
- 是否产生；
- reason code；
- 有界 scalar signal；
- 六维参数族 proposal vector。

不保存完整事实副本、历史 token 副本、eligibility snapshot、节点/边路径或具体目标 ID。

### 生命周期与兼容

- proposal metadata 只在 Stage 3B-3 分配；旧 Stage 3B-2 及更早路径不增加该状态；
- birth 的事件 ring 和提案记录为空；
- death 清除；
- compaction 随稳定主体移动；
- clone 和 checkpoint 精确复制已提交提案；
- v0.113 Stage-3B-2 checkpoint 升级时重建空 proposal arrays，不伪造提案；
- regional branch 继续使用既有统一生命周期；
- disabled 配置继续按旧规则从 canonical identity 中移除。

## 明确未实现

- proposal 到具体 node/edge slot 的绑定；
- 使用 historical-tick eligibility snapshot；
- 避免同 tick eligibility 混合的最终写入协议；
- eligibility modulation；
- node bias、gate、edge parameter、retained state 或 topology 更新；
- reward、valence、polarity、utility 或固定后果价值；
- causal credit 的科学判断；
- proposal acceptance、rejection policy 或稳定性审计；
- 单次、累计和代际塑性预算；
- 可塑性物理成本与资源扣除；
- proposal readout 的 mutation 或发育表达；
- GPU Stage 3 执行；
- Epoch 1 panel、主体性评分或涌现结论。

## 为什么仍不执行参数写入

当前 local eligibility 表示近期局部活动，但尚未绑定到被关联历史 token 产生时的精确局部状态。若直接把当前提案乘到当前 eligibility，可能错误更新候选事件之后才活跃的节点和边，形成同 tick 或跨 tick 污染。

因此 v0.114 只把“历史候选 + 客观事实对比 + 图自产生的投影和方向”压缩成参数族级提案。具体目标绑定、历史局部载体一致性、更新稳定性和物理成本必须在后续独立阶段冻结。

## 下一授权边界

下一阶段应先实现 Stage 3C-1 proposal target binding contract，至少回答：

1. 如何把参数族提案绑定到仍有效的具体局部 eligibility，而不恢复长期全路径记录；
2. 如何证明目标资格来自历史候选的允许时间窗口，而不是当前 tick 的新活动；
3. 如何允许拒绝、裁剪和容量不足；
4. 如何在不写参数的前提下保存可审计的具体 target proposal；
5. checkpoint、clone、birth、death 和 compaction 如何保持稳定目标身份；
6. 在参数写入前如何单独冻结稳定性、成本和累计预算。

在该合同完成前，不授权任何参数写入。

## 科学证据边界

本轮只能证明：统一主体图能够在已有历史候选基础上，使用自行产生的连续控制量和角色中性客观事实对比，生成一个有界、可拒绝、参数族级别的调制提案，并经生命周期和 checkpoint 保存。

它不能证明候选具有真实因果性，不能证明实体已经形成价值、偏好、学习、记忆理解、主体性或涌现。
