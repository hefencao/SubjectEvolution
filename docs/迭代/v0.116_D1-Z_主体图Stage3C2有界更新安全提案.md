# v0.116 D1-Z：主体图 Stage 3C-2 有界更新安全提案

## 1. 本轮目标

本轮在 v0.115 已完成的具体 target binding 上，生成有界、可拒绝、可审计的候选参数 delta。仍不执行永久参数写入，不把客观事件变化解释为固定价值，也不把 bootstrap 公式宣称为最终通用学习机制。

## 2. 已实现

### 2.1 精确目标再验证

每个已绑定目标在形成 delta 前重新检查：

- node/edge 类型与参数族匹配；
- 固定槽位仍在容量范围内；
- stable node/edge ID 未改变；
- 目标仍处于 expressed 状态；
- input/output/trace gate 目标仍具有对应端口；
- 当前参数值有限。

任何失败都产生角色中性的拒绝原因，不尝试改绑其他目标。

### 2.2 Bootstrap 三因子候选

候选公式为：

```text
参数族提案 × 激活前历史局部 eligibility × 配置步长
```

这只是帮助早期塑形和调试的通用工程偏置。eligibility 的符号仍是局部计算方向；客观事实的方向由图产生的投影控制；引擎没有提供 reward、valence 或 polarity。

### 2.3 数值安全边界

候选依次经过：

1. 每参数族绝对 delta clip；
2. 每主体每事件 L1 预算；
3. 超预算时按比例缩放全部有效候选，避免参数族顺序决定优先级；
4. 参数 lower/upper bound 投影；
5. 最小有效 delta 检查。

edge bandwidth 的下界必须非负。

### 2.4 Compare-and-swap 与 rollback 守卫

每个候选保存：

- expected current parameter value；
- raw candidate delta；
- bounded candidate delta；
- projected parameter value；
- family clip、event budget 和 parameter bound 是否生效。

expected current value 只是未来原子写入和回滚的守卫。本轮没有 apply 函数，也没有参数写权限。

## 3. 明确未实现

本轮没有：

- permanent parameter write；
- eligibility、retained state 或 topology 写入；
- 多参数原子事务；
- rollback 执行；
- accepted/applied update ledger；
- 长窗口实际更新预算扣减；
- physical plasticity cost debit；
- 通用注意力候选分配器；
- Epoch 1、学习成功或主体性结论。

未执行的 audit proposal 不计入“已应用更新”预算，否则会虚构不存在的可塑性并阻断后续真实候选。

## 4. 生命周期与兼容

- committed update-safety metadata 随 event ring 参与 clone、checkpoint、compaction 和 death 清理；
- birth 的 graph structure 可以继承，但事件与 update proposal 历史为空；
- v0.115 Stage 3C-1 checkpoint 恢复为原图与 binding 状态，并新建空 update-safety metadata；
- disabled update-safety 配置从 canonical identity 中移除；
- CPU reference 路径不增加 RNG 消费，不改变 action output。

## 5. 科学边界

本轮只能证明：

> 已绑定的历史局部载体和图产生的参数族提案，可以在目标身份重新验证后形成受多重数值边界约束、带回滚守卫的候选 delta，而不修改主体图。

它不能证明候选具有真实因果性、方向正确、能够改善行为，或已经发生学习。

## 6. 下一授权边界

下一阶段应冻结 Stage 3C-3 原子 apply dry-run/transaction 合同：

- exact compare-and-swap；
- 同事件多目标 all-or-none；
- rollback record；
- accepted/applied 累计预算；
- count-only plasticity cost；
- 仍先以 dry-run 或显式禁用写入方式验证，再决定是否授权永久参数变化。
