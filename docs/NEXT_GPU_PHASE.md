# 下一阶段：暂停性能迁移，先完成严格演化基础

v0.2 已固定提案→意图→结算→提交边界，v0.4 已接入混合 GPU 路径。阶段 8.5 之后多轮迁移只降低局部耗时或传输字节，没有稳定改善 100k/300 tick 端到端墙钟，因此性能迁移继续暂停。当前优先级回到科学基础：除物理/模型约束外，策略和主体相关数据必须由生成、观察、继承、突变、交互和选择产生。

GPU版本不得一次性重写全部逻辑。建议按以下顺序迁移，并在每步与CPU参考输出比较：

1. 无状态随机键和基础分布；（v0.3 已完成；v0.4 已融合 GPU SplitMix64 键生成并保持位级对照）
2. 环境资源与信息场；（v0.3 已完成；v0.4 使用后端无关的稀疏 `SignalEmissionPlan`，高频事件可追加到低频目标通道的待发队列，到期时合并而不创建零列）
3. 规则网格、排序和伙伴采样；（v0.3 已完成）
4. 观察构建；（v0.4 已完成；阶段 8.5 将 CPU 批量解码结果改为稀疏 `DirectMessageObservationPlan`，GPU 只为实际接收者构造紧凑固定槽）
5. 演化策略批处理；（已完成结构修正：128 个行动偏好权重进入可遗传/突变基因组，固定代码只定义特征和行动语义）
6. 移动与采集冲突；（采集设备归约和 `GpuActionConflictResolver` 的只读采集计划已完成；稳定实体/社会字段设备缓存。移动当前没有共享冲突，仍由统一 CPU 提交写位置）
7. 分享、关系事件和固定槽位；（`ShareResolution → RelationUpdatePlan → 固定槽提交` 边界已完成；事件含来源/方向/tick，CPU 固定槽应用已优化，尚未迁移设备驻留关系表）
8. 出生死亡与空闲槽位；（`BirthRequestPlan → BirthAllocationPlan → CPU commit` 与 `DeathEventPlan → CPU commit` 已完成；槽池版本令牌拒绝陈旧计划，尚未迁移设备驻留槽池）
9. 插入性能阶段 8.5：直接消息观察与传输审计；（已完成；CPU 固定槽语义保留，GPU 不再上传 `active × capacity` 零填充张量，整步显式 H2D/D2H 字节进入指标）
10. 阶段 9：群体标签传播；（已完成；`GroupDetectionSnapshot → GroupLabelPlan → Social/CandidateGraph commit`，成员一次规范分段，主体摘要增量维护）
11. 阶段 10：持久设备实体状态与统一提交计划；（已完成；版本化 `EntityDeviceCommitPlan`，高密度连续 DMA，位置/生命周期/社会字段按密度选择规范补丁）
12. 阶段 11：GPU→CPU 提交视图压缩；（暂停；仅在端到端剖析证明下载和 CPU 消费边界为主瓶颈后恢复）
13. 阶段 12：指标归约和异步日志；（暂停；日志已有窗口墙钟，不再以局部 step 指标推断收益）

阶段 6–10 的规划/解析实现只能读取快照、写入计划或事件缓冲；不得让策略、观察或解析内核直接改写世界。消费已解析计划的提交执行器则允许位于 CPU、GPU 或未来分布式分区，但必须保持单写者、版本校验、可回放输入和清晰同步点。这个“受控提交”边界取代“CPU 永远是唯一写者”的旧表述，避免把当前混合实现固化为架构约束。

多个控制器也必须先形成 `ControlProposalBatch`，再由仲裁器产生统一决策；不得把社会、谱系或 Hero 控制逻辑嵌入某个动作内核。当前已实现默认关闭的双提案社会方向控制：它只混合既有 `MOVE_RESOURCE` 方向，并以完整贡献数组记录身体和社会来源。方向混合是显式建模规则；它不等同于动作级多控制器理论的证明。

阶段 9 已完成。群体检测现在从只读关系/活动实体快照生成可替换的规范计划，计划同时携带实体标签、群体聚合和 group/member 分段；社会状态与候选主体图是两个独立单写者。主体图不再为每个群体重复扫描全部 active slots，summary 也不再遍历全部历史节点。100k active、45,016 成员、2,648 群体的隔离提交基准由约 `0.335–0.353秒` 降至约 `0.0244秒`，预热中位数约 `14.1×`；21 万历史节点的 summary 由约 `14.1ms` 降至约 `0.36µs`。100k/300 tick 严格 GPU 两次为 `27.72/29.14秒`，动作计数、出生死亡、最终离散状态和传输字节与阶段 8.5 完全一致，但相对阶段 8.5 的 `25.55/27.14秒` 不构成端到端提升：该配置只有 tick 200 的群体提交足够大，隔离收益被逐 tick GPU 路径与机器状态波动淹没。

阶段 10 已完成。`DeviceEntityState` 现在持久保存空间、策略和社会观察所需字段；CPU 世界提交后发布带 `base_version → next_version` 的 `EntityDeviceCommitPlan`，设备拒绝重复或陈旧计划。动态状态、位置、生命周期静态值和社会字段使用独立密度决策：变更达到容量 50% 时进入连续 DMA，否则按严格升序索引提交。50% 是明确记录的执行启发式，只选择等价传输形式，不改变模型、随机键或浮点运算。出生/死亡不再触发整张 stable ID、genotype 和社会数组上传；外部干预仍可请求一次完整修复。

100k/300 tick 严格 GPU 最终运行是 `27.62秒`，动作计数、出生死亡、群体、主体边和图版本与阶段 8.5 逐项一致。tick 300 H2D 从 `16,788,152` 降至 `9,345,128 bytes`，减少 `7,443,024 bytes`（44.3%）；其中实体提交计划为 `5,270,960 bytes`，设备提交约 `2.49ms`。D2H 仍为 `10,436,876 bytes`，墙钟落在阶段 9 的 `27.72–29.14秒` 波动区间，因此不宣称端到端提速。开发中验证并淘汰了“所有字段一律稀疏散射”的版本：它虽将 H2D 降到约 `9.78MB`，但每 tick 多个散射核和重复 `np.unique` 使 300 tick 恶化到 `34.84秒`；密度感知连续复制和复用上游规范索引后才恢复到当前结果。

`HostCommitView` 不再是当前下一步。设备→主机流量虽超过主机→设备流量，但阶段 10 已证明减少字节不等于降低墙钟；继续压缩完整观察张量还会扩大临时双重表示。恢复性能迁移前必须重新剖析完整 300 tick，给出总墙钟占比、迁移后可消除的同步次数以及端到端验收阈值。

## GPU 写入边界与未来迁移价值

当前 GPU 模式已经由设备权威更新环境/信息场并提交采集扣减，结束或交互检查时才同步主机镜像；实体、关系、生命周期和主体图仍由 CPU 权威提交。下一轮设备迁移不再按“找到一个 CPU 函数就搬一个核”推进，而按能否形成完整驻留域评估：

| 候选域 | 价值判断 | 恢复条件 |
|---|---|---|
| 行动解析 + 位置/能量/维护成本 + 实体提交 | 高 | 作为一个连贯事务迁移，保留 `ActionResolutionPlan`、版本和来源审计；能消除每 tick 大型决策/最终状态往返 |
| 固定关系槽 + 群体标签读取 | 中高 | 关系表与消费它的群体阶段共同驻留；不能只迁移事件排序后又整表回传 |
| 生命周期 + 活动集 + 空闲槽池 | 中 | 与权威实体 SoA 同时迁移；单独搬出生/死亡扫描收益不足且会制造双写 |
| 控制/意图压缩边界 | 中 | 先明确 CPU 提交真正需要的最小、可审计列，并证明可减少同步而非仅减少字节 |
| 候选主体历史图、CSV/检查点、低频群体图提交 | 低 | 保持 CPU；除非实测成为持续主瓶颈，不为设备化限制动态历史结构 |
| 直接消息 CPU 队列的孤立迁移 | 低 | 只有在消息所有权、延迟桶、接收裁决与策略消费能形成完整驻留域时才重议 |

以上优先级是架构评估，不授权立即迁移。当前性能工作暂停，任何恢复项都必须同时满足：端到端剖析命中、不会引入双重权威状态、固定种子语义对照通过、100k/300 tick 墙钟达到预先设定的显著阈值。

## 当前功能阶段：严格演化基础

基础策略已从“固定行为公式 + 8 个调节潜变量”改为“固定行动/传感约束 + 128 个演化权重”。突变发生率与幅度已分离，避免每次出生扰动全部策略基因。每 500 tick 的独立评估不再把原始权重方差当作策略多样性，而是报告世代、有效谱系、规范策略、有效维度和固定探针行为概率。默认 `scientific` 协议拒绝采样后的行动或方向覆盖。

候选社会主体现在累计实际分享能量的内部留存、跨边界流出和外部流入，并输出加权/平均利益边界内聚。该测量不会改变群体或行动，但群体关系本身来自分享，仍需用额外利益通道和滞后窗口消除循环定义。

干预阶段降为次优先级，但其扩展边界已固定：修改存在、环境和规则的观察性干预与直接行动控制分开登记；未来可增加 `introduce-existence`。`independent-foraging-v1` 和社会方向覆盖被保留为娱乐功能，必须显式选择 `entertainment`，其结果不得解释为自主性或主体偏移。

单种子 2,000 tick 已覆盖四个评估窗口：平均世代仅到 `3.57`，但有效谱系从约 `731` 降至 `45`，规范策略/固定探针行为多样性仍为初始的 `97.75%/99.29%`。这表明结构性谱系集中已发生，策略选择响应仍弱；下一步应做多种子和环境/行动收益消融，增加不预设期望行动的多尺度生态权衡，并报告策略—物理后果—繁殖机会的关联，而不是用一个“多样性”数值判断全部坍缩。

知识层评估结论是采用动态知识单元、承载体副本和有代价交换，不采用集中式大规模 RL；实施顺序为数据/成本守恒 → 局部后果学习 → 新策略 schema 的稀疏知识残差 → 知识候选主体。详见 `KNOWLEDGE_ARCHITECTURE.md`。

对外部架构建议的取舍如下：统一 Array API 适合抽取无状态数值核，但当前 CPU `Environment/InformationSystem` 与设备对象承担不同的持久状态和队列所有权，现阶段强行合类会模糊同步边界；候选主体图的重复扫描问题已经用规范分段解决，不采用固定 `max_edges` 的全量扁平重写，以免限制历史边和未来主体类型；确定性 `lexsort` 仍是严格模式基线，任何非确定 fast mode 必须作为显式实验模式并单独验证；CuPy 已有内存池，自定义 scratchpad 需先由分配剖析证明；`ControlArbiter` 协议已经接受任意提案批次，职责链是可选实现而不是核心接口前置条件。阶段 9 没有新增模型启发式，固定 8 轮标签传播仍是原有、已文档化的近似群体识别规则。

每一阶段必须提供：

- CPU/GPU固定种子小场景；
- 随机分布统计对比；
- 离散事件一致或明确的统计容差；
- 性能剖析；
- 不允许策略读取新增的GPU内部真值。
